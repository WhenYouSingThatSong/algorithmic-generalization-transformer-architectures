# 两个优先试验：输入对齐诊断 + 合法重新赋值

2026-11-18。对应研究索引 **E2/E4 + M1**、**W1/W2**。
本批只使用现有权重；不训练C+、不复用物理槽位、不扩图规模、不改历史实验源码。
具体服务器交接见[执行与验收](../../ai-collab/handoff/2026-11-18-priority-pilots.md)。

## 1. C：输入对齐的读出/下游观察

入口：`function_audit.py`，只用Python标准库，读取已有完整记录，不需要GPU、权重或NumPy。

支持：
- `C_uq_pair_eval_v1`：单次父子干预，实际下一轮输入读出由initial/上一轮输出重建。
- `C_stress_v1`：持续污染和噪声，必须使用记录中的每轮实际inputs，不能用上一轮outputs代替。
- 当前来源固定为ADD mod23，数值token ID为0–22；不接受其他任务直接套公式。

每条u→q边、每轮同时记录：
1. 输入u读出是否正确、输出u读出是否正确、输出q是否正确；
2. 输入q是否已有正确答案，其余父节点VALUE/四属性是否正确；
3. 输入父读出代入ADD的结果与q输出是否相同；
4. 与匹配参照相比是否新增q损伤；
5. 强制/释放阶段、绝对输出轮次、缺数值状态。

父子同时污染使用“只污染q”的参照；持续污染的q_wrong分支使用free_q_wrong，避免把直接污染q的后果全算给u。参照对应的分支名保留。
“按输入父值计算一致”只是C隐藏反馈中的**读出关系**，不是证明模型内部采用了这些数值。

产物：
- `edge_rounds.csv`：全轮次逐边证据，input轴与output轴同时保留。
- `quadrants.csv`：u读出对/错×q输出对/错，分输入轴/输出轴、来源、模型、时点、持续长度、分支、轮次和受控子集；原始边数/图数/图均权比例。
- `events.csv`：q首次输出错、首次回正、窗口内最终稳定段、多次反复；不能当因果纠错成功率。
- `coverage.csv`：已有记录自身资格和跨模型/持续长度共同资格。all_recorded只包括原选点成功且写入记录的图，原候选缺失须结合来源coverage。
- `meta.json`：来源/代码hash、来源完整meta及分母。没有案例时不填100%。

用途是确定接下来的功能干预需要排除什么，不把已有q输出叫成“已经证明的功能探针”。健康q保持正确，仍可能是复制旧值；父值读对，仍可能有其他隐藏成分异常。

## 2. A′/B：旧任务出错与新题面更新

入口：`run_reassignment.py`；汇总：`summarize_reassignment.py`。只支持离散ADD mod23。
沿用N32主manifest、A′ s42/e86和B s42/e92，严格核对权重/数据hash。

固定候选graph32–63，共32图，不补样。每图按固定hash选1个有下游的叶变量及其题面常数；选点不看本次模型表现。delta固定1/3/7/11，取模23，不限定4→5。

起点沿用manifest的首次共同完成T，但执行时重新核对该模型：
- 原题所有非PAD位置前四字段必须与旧label一致，所有数值节点必须正确；
- 不合格写selection，不找更晚轮次或别的图补足；
- 比旧机制试验更严格，是为了先排除旧题结构已漂移的干扰。不能把本批资格率与旧VALUE-only口径直接对比。

每个case七分支，额外自由观察H=16：

| 分支 | 初始操作 | 正确真值 |
|---|---|---|
| clean | 完成状态原样续算 | 旧 |
| sham | 叶节点正确VALUE原样写回 | 旧 |
| state_error | 题面不变，仅叶变量VALUE加delta | 旧 |
| new_warm | 只改题面常数，保留旧节点答案 | 新 |
| new_scratch | 从原始未求解输入开始，只改同一常数 | 新 |
| new_warm_pinned | 与new_warm相同，每轮输入固定该常数VALUE | 新 |
| new_scratch_pinned | 与new_scratch相同，每轮输入固定该常数VALUE | 新 |

pinned仅固定这个常数的VALUE；不固定其他字段、不强制节点答案。记录实际输入以检查常数漂移。pinned是额外信息保障对照，不能冒充纯自由续算。

新真值由独立的ADD拓扑计算得到，旧真值也先通过它复核。真值仅用于标签和统计；新题面只写常数，**不会把计算出的新叶值/下游值灌入new_warm/new_scratch**。
state_error的注错值等于叶变量合法新值，但保留旧题面；因此“相同数值变化”应有不同正确处理。

scratch与warm比较的是同样多的**后续**前向，不是总算力相同：warm已付出完成旧题的T+1轮。每分支保存pre_forward_round，报告需计入这项预先计算。初始时点post0不算模型恢复。

汇总：
- 两模型共同合格case主表，自身合格表附录；全部32图资格单独报告。
- 全节点、叶节点、真值改变节点/下游、抵消后真值不变的下游、所有真值不变节点、题面常数分开。
- 前四属性联合正确、VALUE正确；每轮、末两轮同时正确；old/new正确数并列。
- graph均权与节点原始计数分开，delta单列；空区域记空，不记100%。
- `case_curves.csv`包含实际输入/输出常数、新真值匹配和真值不变节点相对clean的新增损伤。
- `paired_models.csv`只比较共同case；`warm_vs_scratch.csv`比较同后续预算，pinned与free分开。

本批回答能否适应合法的新题面，不证明已经学会槽位释放/版本化，也不证明突破128节点。

## 3. 本地检查与服务器职责

本地11项stdlib测试覆盖实际四格汇总、图均权/节点加权差异、持续强制输入、配对q污染参照、缺值、反复恢复、独立新真值/模抵消、输入只改指定槽、新旧真值汇总、末两轮和空分母。三个CLI的help通过。

本地无PyTorch/服务器权重，未运行真实模型。服务器执行agent完成依赖检查、W两图四轮小验证后，再按固定范围执行。实现语义变化须反馈；路径/设备适配可记录后处理。结果无收益也可验收，代码/时序/真值不合格不可验收。
