## 共同规则

- 起点轮次统一为 **已完成的forward数量**。在第t轮输出状态上改动，`outputs[0]`是第t+1轮输出；`initial`是改动后、尚未继续计算的读出。
- 原异常用于检查操作；其它图按固定规则取样，成功与失败都保留。不同起点、案例组、权重分开报告。不得用干预结果重新选样或更换权重。
- 每个目标记录全部数值节点的四属性；目标、父节点、下游、局部范围外其它节点分别统计。零节点的分母记空，不赋100%。
- 主要看：第一轮/逐轮正确率、最后两轮是否均正确、相对于同起点不改动分支的改善和损伤。初始替换立刻读对，不算模型通过后续计算修复。
- 保存来源哈希、实际起点、样本资格和未纳入原因。所有输出目录必须新建，不覆盖既有实验。共享服务器工作树串行同步；正在运行的目录不pull。

## B：父值正确时，已有答案是否被覆盖

**权重：**沿用主manifest的A′ s42/e86与B s42/e92。每个权重单独运行，汇总只比较两者共同合格的主实验目标。模型、数据与manifest哈希必须对应。

**固定样本：**现有N32主manifest中graph32–95，共64张候选；使用已有目标链，不按本次恢复效果选点，不补样。它们与graph142等异常图分开，但曾参与先前实验，不能称为从未使用的最终测试集。

对每个目标取两个时点：①在原manifest规定的求解预算内，该模型第一次实际输出目标正确值的时点；②原manifest中两模型首次共同整图数值全对时。均要求目标及其全部数值父节点正确；第一个时点若父值不正确，就判不合格，不能换个后来算对的时点补上。A′/B的首次正确轮次可以不同，实际轮次保留在记录中；同一时点类型只比较共同合格目标。这是新的首次正确定义，不直接复用旧实验的按深度对齐时点。

从完全相同的状态分出5份：

| 分支 | 实际操作 |
|---|---|
| unchanged | 不改任何值 |
| correct_write | 向目标写入正确值，检查相同输入操作 |
| wrong_plus_1 | 目标正确值加1，取模23 |
| wrong_plus_3 | 目标正确值加3，取模23 |
| empty | 清空目标VALUE |

只改目标VALUE一次，随后自由运行16轮；父值并不被每轮强制固定。记录它们是否后来变化，因此不能把整段窗口都解释成“父值始终正确”。其它字段沿用现有离散评估处理，两个辅助字段置FALSE。

先两个候选图、4轮验证，再固定64图、16轮。首批不增加节点数、训练种子、方程重排或64轮新预算。其它值/位置/时点已提供第一批跨场景变化，之后根据结果决定追加。

## C：自然错误分类与局部连续向量替换

**权重/来源：**旧C₀ s42/e143与s1234/e143，已有六档、每档64图的64轮NPZ，以及对应原始PT。先CPU选样，再少量案例重放。不是重跑整批能力评测。

### 先描述所有候选事件

`select_c.py`读取实际预测而非直接相信正确标志。每个有数值父节点的非叶节点，找整图首次数值全对之后首次“数值正确→错误”。父值类别按**出错forward之前**的上一轮读出区分：全部正确、有数值错误、含EMPTY/N/A。也记录把父读出代入ADD mod23得到的预期值。

未曾整图完成的图另按整条轨迹记录事件，标为`not_yet_complete`，本批替换不纳入；不是丢掉这些图或宣称它们没问题。若完成后数值始终保持、但变量名发生正确→错误，则记录`variable_only`对照。叶节点没有数值父节点，本批不做局部父状态替换，后续可单独研究。

所有事件保留在`candidates.jsonl`。分类只是**读出行为关系**：C传递hidden，错父读出代入一致不等于内部真的使用了离散父值。

### 怎样选替换案例与向量

- 错误现场t：上述事件出现的那轮输出hidden，不等到事后挑选最好救的时点。
- 来源s：在t之前，目标及全部数值父节点的**VALUE均正确**的最近一轮hidden。来源的目标/父节点四属性是否全对另行记录，不把“数值正确”写成整个表示正确。这样不会因变量名先漂移而被迫只使用很早的向量。找不到则列入缺失，不凭空造向量。
- 按权重×数据档×错误类别×自然结局（末两轮目标VALUE正确/不全正确）分组，各选1个案例，组内用固定seed=20261115的哈希顺序，优先不同图。VARIABLE-only单列。每个组不足如实报告，不为了凑数改变规则。
- 先取已完成图事件，且至少剩2轮原记录供重放比对。此为按事件和自然结局分层的**诊断样本**，其平均成功率不能推广为总体发生率；汇总保持自然结局组分开。
- 健康对照：在同图更早的整图数值正确时点t′，找到相同间隔(t−s)的数值正确来源s′。目标/父节点VALUE须正确。没有就单列缺失，不能缩短间隔替代。这个对照匹配向量年龄，但不意味着变量名读出或整个隐藏状态分布完全相同。

### 每个现场做四个分支

| 分支 | 实际操作 |
|---|---|
| unchanged | 当前hidden不改动 |
| sham_current_target | 将当前目标向量原样取出、写回 |
| restore_target | 只把目标向量换成同图同位置在s轮的向量 |
| restore_parents | 只把全部数值父节点向量换成同图同位置在s轮的向量 |

改一次后自由续算16轮，始终回灌hidden；没有把解码字段写回，没有每轮钳住正确值。健康对照做同样4分支。观察数值与四属性分别变化、下游改善、其它正确节点是否受损。

替换整个向量会带入多种信息。因此即便有效，也不能直接称为“修复VALUE编码”或“修复变量名”；先回答局部状态替换能否持续改善计算。

### 重放与保存

沿用原run_meta中的batch size和原批次排列/裁剪长度，使用同一权重与数据哈希。只重放包含选中案例的批次，先核对全部64轮数值节点四属性是否与原NPZ一致。再核对不改动续算与已有未来轨迹、原样写回分支与不改动分支一致；不一致停止并报告，不删除难复现案例后继续统计。

每个现场保存完整当前hidden、来源位置及对应向量，置于输出`states/*.pt`；预测轨迹写`records.jsonl`。隐藏快照只留服务器tmp，不上传git。晚于原64轮的新观察明确按实际轮次记录，不混入旧能力表。

## 汇总文件怎么读

`summarize.py`读取已完成运行，输出：

- `coverage.csv`：每个case是否进入汇总。B主样本取A′/B共同合格交集，anchor单列；C缺来源/缺健康对照见选样manifest。
