# C的命名、变量身份漂移与多时点局部纠错

日期：2026-11-20。本文记录已确认目标和首版实现参数；不是新实验结果。代码见[训练入口](../../../tools/c_multitime/README.md)。

## 摘要

当前旧UPDATE后训练在128张dev图上出现：D+16节点VALUE约99.8%，first4约76.1%；两个普通纠错种子的同窗口VALUE为100%，first4为100%/约99.8%。这说明旧UPDATE存在此批长窗口身份漂移，**不等于已经证明其纠错能力更差**。报告见[c-update-small-test.md](c-update-small-test.md)，原始dev记录尚未提交本地复核。

用户确认新方向：中间监督既定位正常新计算，也定位已有值与当前父值不一致的修复。首先修直接局部不一致，父值修正后下一轮处理间接受影响的位置。不同轮次按概率污染，**不要求接收模型先算对**；原先正确/错误/EMPTY仅记录，不决定是否允许注错。此条取代讨论中“先筛选已经正确、否则跳过”的建议。

## 统一展示命名

| 名称 | 身份与状态 |
|---|---|
| C（原始） | 原连续隐藏反馈，当前seed42/1234/2026 |
| C（前沿污染纠错） | 旧机器arm=correction；新可算位置污染，没有第二层过程监督 |
| C（前沿污染＋过程监督UPDATE） | 旧机器arm=update；第二层UPDATE监督＋末层计算/对齐监督 |
| **C（多时点局部纠错＋过程监督UPDATE）** | 本次新实现，配方c_multitime_process_update_v1，先原s2026；尚无服务器验收/训练结果 |

“前沿”指按图深度安排候选时点，不保证连续模型在该时点仍读出EMPTY。UPDATE是过程监督，不是硬门控。旧目录、arm、checkpoint与历史hash不改名；所有正式表带seed/配方/checkpoint。早期保持/噪声/语义后训练是别的批次，保持独立名称。

## 变量身份漂移：已经知道什么，尚不知道什么

数值可由父值和运算重建；随机分配的变量名不能从算术推出。生成器[replace_variable_name](../../../experiments/generate_data.py)按变量词表无放回随机重命名；当前[模型配置](../../../experiments/configs/C0-M4-Nodes32-ADD-L4H16D384-DeBERTa/model_config.yaml)为causal_attn=true；[连续路径](../../../experiments/model.py)循环回灌hidden，并不每轮额外注入一份原始题面。

例：`x_2 ADD x_3 = x_17`，父值能告诉它结果是7，却不能告诉它结果必须叫x_17。若首次定义位置身份受损，后面的x_17引用即使正确，该位置也不能在因果注意力下回读它们。后续引用位置则可能访问前面的定义，但模型是否能找到正确对应关系仍需实证。

需要分开三件事：

1. VARIABLE头读错：原身份可能仍以其他形式存在hidden中。
2. 后续计算真的按错误身份取值：须看实际下游行为，不能由读错直接断言。
3. 身份信息已从所有可访问状态彻底丢失：若无其他约束足以唯一确定，就无法靠反复计算凭空恢复随机名字。

训练标签中的原名能教模型保留信息，但不是推理时可访问的备份。UPDATE监督生成器可用原图metadata生成标签，不表示模型得到了该metadata。当前UPDATE定位规则基于VALUE局部一致性，变量名漂移本身不会自动触发TRUE；前三属性仍有正确性loss。

## 变量漂移的初步分析待办（本批不实施新训练）

1. 用现有轨迹区分首次定义和后续引用位置，统计漂移时刻、持续与恢复；当前节点指标只覆盖定义位置，不能假称已测全部引用。
2. 联合看VARIABLE/ VALUE读出与直接下游行为；特别保留“身份错、值对”而下游仍对或变错的两类。
3. 若进一步做干预：漂移后原样写回 vs 本位置历史正确hidden替换，比较身份与下游恢复；整行替换混入多种信息，不称纯身份因果实验。
4. 更严格的身份信息抹除、重复引用备份、不可变题面通道，均属后续设计，不在本轮自动实现或授权新增训练。

## 新训练的规则及例子

原题a=3、b=2、u=a+b=5、q=u+4=9。输入u被改成7：本轮u应UPDATE并变5，q依照输入u=7应变11；下一轮q再修回9。输入若a=4、u=6，则先修叶a，u当前局部一致先保持6，下一轮再修u。父值非数字则等待；不能把本轮刚修正的父输出提前用于子标签。

第二层定位，第四层监督正确状态和定位/执行对齐、清零；没有门控。延续旧损失1/2/5/.1，不加入身份修复目标。源向量质量检查仍保留，接收端正确性筛选取消：两者不能混淆。

实施默认：50k原数据，原C s2026/e143，50epoch上限；三时点模式等概率，5%有效batch启用、50%结构候选；frontier在depth处、middle在max(1,D//2)、late在D+4。middle/late之后监督D+1轮，全BPTT；具体候选与预算见README。late只是固定预算，不声称完成。实际完成与否记录后用于分析。

增加时点也增加了长程监督预算，损失按各轨迹轮数平均，故新配方整体比较不能唯一归因于中间监督或某种污染；本轮不擅自增加消融组。先一seed跑通，再决定是否扩展。

## 性能与执行边界

默认实际batch32；图结构一次预处理、每轮GPU批量生成目标、日志每batch批量搬出、供体合批。原训练数据/模型主体/精度不改，训练、checkpoint和评估计时分开。最长循环显存须服务器确认，OOM才记录并回退16/8。新目录隔离旧代码，旧任务不重训、不迁移；服务器按串行交接同步。

Agent C执行小验证和新单seed训练，Agent B完成旧批正式评估并在后续接收新权重做同协议对照；次序协调，不打断旧任务。普通纠错版既有dev中已记录受扰轨迹，应优先补交其恢复/下游损伤表，不能只有clean准确率。
