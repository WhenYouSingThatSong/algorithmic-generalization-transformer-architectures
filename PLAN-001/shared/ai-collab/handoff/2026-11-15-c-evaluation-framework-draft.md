# C 模型评估框架：能力、恢复与机制（讨论稿）

2026-11-15 19:14 CST。用户提出先把评估想清楚，再开展三种子正式后训练。本稿记录研究原则与候选设计，不是已批准的新实验矩阵；不启动训练/GPU，既有CPU补交继续。

## 1. 记录：读出与实际计算必须区分

C的监督解码头从hidden读出SYNTAX/VARIABLE/OPERATION/VALUE；下一轮Transformer直接消费hidden。解码结果不作为离散值回灌。因此“读出u=5”与“下游计算实际使用数值5”不是同一事实。下游不是已证实存在的另一个专门计算头；它可能由若干层/注意力/MLP及上下文共同完成。

已确认的是架构的信息路径不同，尚未确认的是二者究竟使用哪些相同/不同的信息。不能把这种可能性写成“模型已存在独立VALUE编码通道”。同样，VARIABLE读出漂移不自动证明内部变量寻址错了。

| 干预后目标读出 | 下游行为（相对同起点clean） | 能说什么 |
|---|---|---|
| 改成指定错值 | 命中该错值的局部代入结果 | 支持扰动确实影响了对应计算，仍不等于唯一机制 |
| 改成指定错值 | 没有观测到影响 | 可能保持已有值、尚未使用该信息、使用其他证据或读出/计算不一致；不能直接称免疫 |
| 未改变读出 | 下游改变/出错 | 只看目标解码不足以表征功能扰动 |
| 未改变读出 | 下游也无变化 | 该条件下未观测到影响，不证明任意扰动都安全 |

下游原本已经有正确答案时，未变化尤其不能当作父信息未被使用的证据。需另设下游尚待计算或已错的情况。

## 2. 第一层：基本能力与长程保持

核心指标沿用用户认可的节点VALUE和节点四属性同时正确；定义位置为变量节点，排除PAD/常数/符号。逐图等权主表，节点总计辅助；叶、内部、输出节点分层，避免只会复制叶值抬高总体表现。

- 正常求解：原输入开始、隐藏状态自由续算；固定轮次准确率曲线、达到给定正确程度的轮数、最终整图率作为辅助。未完成图不删除，不以每题最佳轮次作主成绩。
- 规模/结构：现有N32/64/128、浅/深档作为起点；尽可能匹配或分层深度、父数/分支/下游数量。题面顺序/变量命名若扩展要单独控制，不同时改变多轴后统称规模外推。
- 长程保持：到预定正常预算以后继续运行，分开测首次算对、算对后失错、再恢复及反复出错。节点VALUE与四属性逐字段均保留；达到正确状态的条件子集必须报告覆盖，另报全部图曲线。
- 计算成本：比较相同循环预算的准确率，也报告达到相近准确率所需循环；不因某组修得慢但多跑了轮数就称机制更强。

## 3. 第二层：错误恢复能力

不是完整笛卡尔积。先小而可解释的主矩阵，再将有效、区分度高的场景推广至规模/种子。

主轴：
1. 时点：局部刚算对但下游仍待算；整图已完成；完成后长时间续算。每个时点报告实际状态和资格，而非只凭轮次命名。
2. 位置：可从上游重建的内部节点为主；叶变量与sink分开。叶变量隐藏值损坏（题面常数仍正确）和常数证据本身改动不同，不能混称改根节点。
3. 错误来源：自然错误、可解释VALUE替换、随机向量扰动；VARIABLE身份错误另列探索，先验证其实际信息影响，不能把probe读出变名等同寻址改变。
4. 负荷：先单点一次；再小范围的父/子联合错误与持续污染后释放，检验冗余信息与纠错边界。

每个条件均有同起点clean；向量替换有同值异源对照；随机扰动记录幅度、实际读出错误与功能损伤，而非用相同L2代表相同难度。噪声强度在训练侧/开发集校准，不能在最终测试上挑最有利档位。

恢复指标：
- 注入目标、直接子节点、远端后代、无关节点分开。
- 预定注入次数、实际改变读出数、相对clean曾受损数、曾恢复数、回正后再错、末两轮均正确数分开，空分母NA。
- 保存全窗口，报告首轮与1/2/4/8/16切片；主表保持已认可的末两轮端点，并同时报告第一次恢复和末尾连续正确段起点。不称有限窗口正确为永久稳定。
- 除条件恢复率，还报固定共同样本上的准确率、额外错误轮数/传播范围、健康节点受损率；避免“更容易被打坏”改变分母后反而恢复率更高。
- 自然错误不按输出错误就认定计算错误，尽可能记录下游影响/局部预期；发生率与错误发生后的恢复能力分别报告。

## 4. 第三层：用最少的干预区分机制候选

示例：a=1,b=3,u=a+b=4,v=u+9=13。全部算完后把u换成读出5。

| 条件 | 主要区分什么 |
|---|---|
| u错误、v原本正确 | 是否传播错误，能否保护已有正确答案 |
| u错误、v也错误 | 是仅保留已有答案，还是能重建正确下游 |
| v错误、u正确 | 下游自身是否可由正确父证据修复 |
| u正确、父节点错误 | 是否机械跟随父值重算、是否可维持已有正解 |
| 错父持续若干轮后释放 | 恢复是否依赖上游证据回正；分开维持期/释放期 |
| 原题真的改变，答案应改变 | 抗扰动是否只是冻结、能否适应新的有效证据 |

这些是跨一批图/多种数值/深度的模板，不围绕一个特殊例子无限追查。联合局部错误和真实改题只是候选；本批尚未批准运行。

真实改题需单独设计：连续模型不能像离散模型那样改一个已解码字段就称改变题面。先有新题从原输入求解的参照，再验证对续算状态的证据替换确实表达了新常数/结构；比较新旧真值，不能惩罚正确适应为“没修回旧值”。

机制证据递进：先有逐题联合轨迹（不能拼两组边际均值）；再做上游/自身/下游的受控替换，改变信息来源后看因果效应；只有仍有明确问题时再做层/头干预。注意力可视化或解码准确率单独不能证明信息被用于计算。当前不能宣称识别错误、选择性重算或独立编码通道。

## 5. 能力基准与机制探索分开使用

- 能力基准：固定数据、选择规则、预算、指标；对所有权重统一，结果用来比较配方。独立最终测试图冻结，不据结果换checkpoint/改阈值。
- 机制探索：在开发图上深入干预，解释代表性行为；不把挑选出来的恢复案例当总体成绩。
- 下一步优先用现有C0和hold/noise/semantic权重检查这些评估是否有区分度，先不再训练。CPU补交已经能推进联合轨迹和错误剂量。
- 三种子正式实验仍应在每个C0内完整配对；对不同模型各自状态的干预不可能严格等同，报告共同资格/全固定样本/实际损伤量，并限制跨模型机制归因。
