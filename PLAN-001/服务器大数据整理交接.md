# 给远程 agent 的服务器大数据整理要求

请按本分支的 Research Record 整理服务器上实际存在的训练数据、权重、运行日志与原始轨迹。先用实验设计、训练配置、种子、训练周期、运行回执和已记录的哈希核对身份。服务器实际有哪些文件、是否仍被任务使用，需到现场确认。

1. 以现有工作目录为起点做清单。逐项写原路径、文件或数据集大小、所属计划和实验 ID、使用该文件的任务、是否与其他实验共用。名称相近但身份未确认的文件列成待认领项，保留原位。仓库内原论文的演示权重已归入共享目录。
2. 独属产物归入服务器项目根下的 `PLAN-xxx/EXPERIMENT-xxx/`，按实际内容使用 `config/`、`logs/`、`data/`、`checkpoints/`、`results/`。同一设计的种子及保存点放在同一实验内。共享训练数据和共用起点权重保留一份，登记每个使用方。原始轨迹与从中导出的汇总表分别登记。
3. 对仍在读写、被续训脚本引用或有符号链接依赖的目录，先记录依赖，安排可安全切换的时间。迁移前后核对条目数、字节数和校验值；对归档验证可读性，对断点和配置检查历史脚本能从新位置解析。遇到缺失或冲突时保留现场，记录差异。确认新位置完整、引用可用后再按服务器权限处理旧副本。
4. 回传对照清单：每行含计划/实验 ID、旧位置、新位置、大小、校验值及验证结果。另列缺失、待认领、共享和仍在使用的项目。将清单和简短交接说明交回本分支，在对应实验补路径。服务器的大文件留在服务器，仓库记录可追溯的入口。

本次本地审计只交付这份要求。服务器的清点、迁移和校验状态待远程执行者回传。
