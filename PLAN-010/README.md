# PLAN-010 草稿　连续循环模型的跨轮信息通道：存在性、机制与纠错训练的影响

- 提出：2026-11-27
- 状态：草稿，尚未审阅

## 研究问题

研究者 2026-11-27 提出的判断：离散模型与连续循环模型**最本质的差别在跨轮的信息通道**。

离散模型每一轮把 token 重新嵌入，因此轮与轮之间除已写回的离散字段外不传递信息。即使最好情况——上一轮把该位置读对了——这一轮也只是在「已写回的阶段性状态」上继续。于是监督信号塑造出来的是：**依据本轮状态中可靠的信息，干净地迭代到下一步，不去推进其它位置**；因为即使推进了，也没有通路把它传下去。

连续模型不同：每一轮、每个位置接收的是上一轮输出的完整向量。监督在这种情况下只要求「对应位置在对应轮次能被读出头读出正确的值」，而位置之间的信息传递机制**没有任何约束**。

本计划要追问的是：**在这条额外的、监督触及不到的通道里，连续模型形成了什么机制？**

## 一个必须先说清的事实：两边的监督结构是相同的

实现上，两条损失路径对**每一轮、整条序列的全部位置**都求损失，没有位置掩码。`get_teacher_batch_with_depth(k)` 构造的是「depth ≤ k 的位置填真值、其余填 EMPTY」，因此每一轮的监督要求是：

| 位置状态 | 监督要求 |
| --- | --- |
| depth ≤ 当前轮 | 读出真值 |
| depth > 当前轮 | **读出 EMPTY** |

所以差别不是「监督稠密 vs 稀疏」，而是：

- 离散 A′/B：每轮隐藏态被销毁、重新嵌入，**信息没有地方可留**；
- 连续 C：隐藏态跨轮存活，监督只约束读出、不约束隐藏向量。

换个说法：**监督要求未到轮次的位置输出 EMPTY，等于要求模型把已经知道的东西从读出层藏进隐藏态。** 本计划要检验它到底藏了什么、怎么藏、以及纠错训练会不会改变这个做法。

## 待检验的假设

- **H1 存在性**：C 的隐藏态在节点自身轮次到达之前，已含有该节点的计算结果。
- **H2 载体**：这份信息由连续的隐藏向量承载，而不是可从 token 复原的内容；把跨轮载体换成离散 token 会使行为退化。
- **H3 形成**：该机制不是一轮就能建立的，需要跨轮累积。
- **H4 随机性**：该处没有直接监督，机制的形成对初始条件敏感，必须在多种子上观察才能判断是否稳定。
- **H5 纠错训练的影响**：加入纠错训练（尤其在多个时点施加污染）会改变模型对这条通道的使用方式。

## 1. 第一步：两件事并行

### 1.1 D（连续 + 纠错）多种子从头训练

- 即 PLAN-009 所说的 D：继承 C 的连续回灌，参照 B 引入数值污染，从头训练。
- **两种纠错时点都要有**：
  - **普通纠错**：参照 B 的做法，只在“本轮新可算、输入仍是 EMPTY”的位置注入数值错误；
  - **多时间点纠错**：在上述时点之外，再在其它阶段注入（例如已算对且已写回的位置），使纠错训练覆盖多个时机。
- **训练预算（2026-11-27 研究者确认）**：
  - **3 个种子，优先沿用原来的三个**（连续一侧原为 s42/s1234/s2026）；
  - **200 个周期**，从头训练；
  - **每 50 个周期**（即 50/100/150/200 四个里程碑）保留 `last` 与该阶段**验证最好的三份**权重。
- **现成参考实现**：`tools/c_multitime/` 已实现三种注入时点——`frontier`（t=depth(u)）、`middle`（t=max(1,D//2)）、`late_budget`（t=D+4），共用一个按 batch 等概率抽模式的调度（`spec.py` 的 `MODES`/`schedule`、`multitime_core.py`、`tensor_targets.py`）。**注意它属于后训练 UPDATE 配方**（从 C s2026/e143 起、50 周期，损失含 `L_state + 2 L_locate + 5 L_align + 0.1 L_clear` 与第二层定位监督），与本计划要的“D = C + 纠错训练”不同。**可复用的是时点调度与污染注入机制，不可照搬其额外损失项。**
- **多种子**从头训练。依据是 H4：该机制缺少直接监督，单种子的观察不足以判断稳定性。
- **变体与规模**：两种纠错时点各一套配方、各 3 个种子，共 **6 个从头训练的 run**（普通 × 3、多时间点 × 3）。
- **与 C 对齐的口径**：C 现有两代可用的 200 周期权重——旧主权重是 150 周期时的 e143（s42/s1234/s2026），续训后 200 窗口内最好的是 s42 的 e177（见 2026-11-27 续训记录）。**D 训到 200 周期，比较时应与 C 的 200 周期权重对，而不是 e143**，否则两边预算不一致。
- **算力估计**：依据本轮续训实测（单周期约 4–5 分钟），单次 200 周期约 13–17 小时；6 个 run 若 6 张卡并行，墙钟约 13–17 小时。
- 与 C 对齐的部分：训练集、验证集、骨干、训练预算、推理轮数。使 D 与 C 的差别只剩纠错训练这一项。

### 1.2 在现有 C 权重上的小验证与初步机制分析

- **小验证（关闭信道）**：不重训，只在推理期阻断跨轮的隐藏通道，观察性能是否退化。这是**存在性**的最省成本检验。
- **初步机制分析**：落点是**父子表达式在序列上相隔很远、中间夹着大量无关表达式的位置**——也就是离散 A′/B 性能退化的那类位置（2026-11-27 研究者明确）。在这类位置上比较隐藏态与读出的关系，看连续模型是否在远距离依赖上用了不同于近距离的信息通路。
- **执行顺序（研究者 2026-11-27 同意）**：先做探针（证明隐藏态里有没有结果信息），再做关闭信道。理由是探针为前置判据：若探针为负，关闭信道的解读会失去前提。
- 材料：现有 C 各代权重（旧 C0 三种子、当前 C0 的两条验证流），以及已归档的早期权重。这些材料已经在本地，不需要等新训练。

## 3. 验证设计（2026-11-28 已成稿并实现）

设计与依据单独成文：[探针与关闭信道：设计与依据](../docs/records/2026-11-28/probe-and-channel-shutdown-design.md)；实现：[tools/c_channel_probe/probe.py](../tools/c_channel_probe/probe.py)。

要点：探针落在**产出 EMPTY 读出的那些隐藏态**（`h_{t+1}[u]`，t < depth(u)）上，避免与“当场算出来”混淆；按 lead = depth − t 分组报告；三个控制（父值改动检验信息是否跟随输入、无关叶子安慰剂、位置置换负控）；两个关闭信道变体（移除载体、冻结未到轮次）外加一个离散写回版本。

**仍未做**：用注入噪声或消融探针方向证明因果。留待探针结果出来后再定。

## 4. 补充：草稿信息（研究者 2026-11-27 允许先记，避免遗忘）

以下内容尚未成稿，只是把待定与已定的细节记下来。

### 4.1 已定

- **“交错”的含义**：子节点的表达式与其依赖的父表达式在序列上相隔很远、中间夹着大量无关表达式。这类位置是离散 A′/B 性能退化处，因此作为机制分析的主要落点。
- **训练预算**：3 个种子（优先沿用原三个）、200 周期从头训练、每 50 周期保留 `last` 与该阶段验证最好的三份。
- **执行顺序**：先探针、后关闭信道。
- **多时点注入的参考实现**：`tools/c_multitime/`，三种时点 `frontier`/`middle`/`late_budget`。

### 4.2 已定（续）与仍待定

**已定**：

1. **注入层次是隐藏状态，不是 token**（研究者 2026-11-28）。替换的内容已核实：把接收位置**整行 hidden 向量**换成一个**供体向量**，供体的造法是——取该题、把叶常数按 `delta` 改动使目标位置的反事实真值变为“原真值 + delta”，用当前权重跑 `age` 轮，取该位置的隐藏行，detach，并做读出检查（前三属性须等于原值、VALUE 须等于改动后的值）；检查不过则该次不注入但保留在分母里。见 `tools/c_multitime/multitime_core.py` 的 `make_donors` 与循环里的 `h[bi,pos] = where(passed, vectors, old)`。
2. **普通纠错不需要另写：`frontier` 模式即是**。它的时点是 `t=depth(u)`，正好是“本轮要更新的那个位置”，也就是当初对照 B 的那一档。
3. **剂量可与 B 对齐，但只有 `frontier` 单用时才真的对齐**。`spec.py` 里 `batch_probability=.05`、`position_probability=.5`，与 B 的 0.05 / 0.5 是同一档名义概率。README 那句“不宣称实际剂量与 B 相等”说的是**候选集合**不同，导致每张图实际被注入的条数不同：

   | 模式 | 候选集合 | 落在几轮 | 每图候选数 |
   | --- | --- | --- | --- |
   | `frontier` | 全部结果节点，各自在 `t=depth(u)` | 分散到每一轮 | 结果节点数 |
   | `middle` | `depth < max(1,D//2)` 的节点 | **集中在一轮** `t=max(1,D//2)` | 浅层节点数 |
   | `late_budget` | 全部结果节点 | **集中在一轮** `t=D+4` | 结果节点数 |

   每个候选再独立 50% 抽签。所以 **`frontier` 与 B 同档**（B 的 `last` 也是“本轮新可算的那一批”）；三档等概率混合时，每图期望注入条数约为 `0.5×(n全部 + n浅层 + n全部)/3`，比只用 `frontier` 多。**D 若要与 B 严格对齐，就只用 `frontier`；多时点要另报剂量。**
4. **不使用过程监督**（研究者 2026-11-28）：不引入 `L_locate` / `L_align` / `L_clear`，也不做第二层定位监督。D 只保留“连续回灌 + 数值污染”。

**仍待定**：

1. **“已算对再改错”属于 `middle` / `late_budget`，不属于 `frontier`。** 这里更正本文早先稿的一个说法。核实循环顺序后：注入发生在**该轮 forward 之前**（`h[bi,pos]=...` 在 `rt.forward` 之前），而 `previous` 记录的是上一轮的读出。`frontier` 的时点是 `t=depth(u)`，该位置在上一轮的监督要求下**只能读出 EMPTY**，所以注入时它并不“已算对”。真正“已算对再改错”的是 `middle`（`t=max(1,D//2)`，候选为 `depth < t` 的节点）与 `late_budget`（`t=D+4`，候选为全部结果节点）：这些节点按深度本应已读出正确值。**这正是多时点相对 `frontier` 的实质增量。**
2. **`receiver_correctness_filter` 目前没有实现**，只是 `spec.py` 的 `RECIPE` 里一个取值为 `False` 的键，代码中没有对应逻辑。若要按“接收端是否已算对”做筛选，需要新写。
3. **多时点的具体设计要重定**。原有三档是 `frontier` / `middle` / `late_budget`。研究者指出三档已存在，但**我们这一版要设计成什么**（沿用三档、只取其中两档、还是按“远距离父子”那个落点另设时点）尚未确定。
4. **是否设“只换时点、不改剂量”的对照**，以便把差别归因于时点而非剂量。
5. **注入来源要留成可替换的钩子**（研究者 2026-11-28）：现在供体固定为“反事实图跑 age 轮的隐藏行”，但后续可能改用别的来源（例如沿某个方向扰动、用另一份权重的状态、对自身状态加噪等）。因此实现时**把“供体构造”抽成一个可替换的接口**，而不是写死在训练循环里。

### 4.6 为什么第一步不把“干净求解”当主判据

2026-11-27 的续训前后对比（[记录](../docs/records/2026-11-27/eval-before-after-s42.md)）显示：在独立留出集上，A′、B、C 的干净求解都已接近上限（八份权重里五份的三项指标 ≥ 0.9995），该判据对这些权重几乎没有分辨力。因此 D 与 C 的对照应落在行为判据上（保持与改写、错误传播与持续恢复），干净求解只作同题拟合水平的记录。

### 4.7 探针实现与 smoke 发现

- **图解析已验证**：从 token 序列解析 DAG 后按“父值之和 mod 23”重算，4 题的全部结果节点与标签**逐个吻合、0 失败**。这是所有干预的前提。
- **探针必须同时报 train acc**：首版在 4 题、260 训练样本上 train acc = 1.0 而 val acc ≈ 随机，属过拟合，不能读作“无信号”。已加入 train acc 输出，并要求任何探针读数都同时给出 train/val。
- 实现中修过两处错误：① 单父节点写成 `x_a = x_b`（无运算符）时被解析器跳过，导致父变量缺值；② 新版 sklearn 不再接受 `multi_class` 参数。
- 关闭信道变体的初步读数（4 题，仅管线验证）：移除载体后 node_acc 降到随机水平；冻结未到轮次后 node_acc 约 0.55、整图正确率为 0。**样本太小，不作为结论。**

## 5. 边界

- 第一步只处理 C 与 D，不扩展 A′/B 的行为评测。
- 1.2 的小验证只能说明通道「被用到」或「没被用到」，不能单独区分「预计算」与「信息搬运」；后者需要第 3 节的控制条件。
- 多种子结论在完成前不得外推为「连续模型的普遍性质」。
- 本计划不改变 PLAN-009 已冻结的选点与评测口径。
