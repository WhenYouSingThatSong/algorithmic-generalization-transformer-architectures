# AI 协作目录

本目录是项目内被 git 跟踪的 AI 协作区，2026-11-14 起为 canonical。`tmp/ai-collab/` 只作历史归档，不再更新。

## 结构

```text
ai-collab/
├── README.md      # 本文件：结构与契约
├── consensus.md   # 共识：已确认的事实、定义、决策
├── board.md       # 看板：现在做什么、下一步、阻塞、review 任务
├── log.md         # 日志：只追加的时间线
└── handoff/       # 可选：长报告、审阅包
```

## 契约

1. **共识**只写已确认内容；不确定的写进看板的“开放问题”。修改共识要在 `log.md` 记一行。
2. **看板**是活文档：任务可以在“进行中 / 待办 / 阻塞 / 最近完成”之间移动；不要删除别人写下的未完成事项，更正用新条目并引用旧条目。
3. **日志**只追加，不改历史；每次启动、停止、提交、推送、review 结论都记一行。
4. 条目格式：`[YYYY-MM-DD HH:MM][user|claude|gpt|kimi] ...`；时间用本机 CST。
5. 结论带证据路径；数据、权重、checkpoint 和分析产物留在 `tmp/`，这里只写路径。
6. 不把 smoke / 单 batch / pipeline 检查写成结果；明确区分“已验证 / 待复核 / 未执行”。
7. 不修改别人正在跑的任务、进程、GPU 或输出目录；需要停/改先协商。
8. 用户是最终决策者；B 机制代码和实验的启动/变更先经用户同意。
9. 不放入权重、原始数据、密钥或 token。
10. **统一协作分支为 `reproduction`**（用户于 2026-11-14 明确确认）。各 agent 从该分支更新、检查、提交与推送，不再自行新建 review 分支交付。开始工作及推送前核对远端进展；若出现并行提交，先整合再普通推送，不强制覆盖。旧审阅分支仅保留历史记录。
11. **职责分工**（用户于 2026-11-14 明确要求长期遵守）：GPT 负责与用户商量研究问题、实验设计、结果解释及必要的源码审阅；其他执行 agent 负责代码实现、运行实验和小规模验证。GPT 不自行扩展防御性测试、重复执行已完成的检查或把验证工作包揽过来。发现具体问题时，交代触发条件、影响和必要验证点，由执行 agent 落实；用户另有明确指派时按最新指派处理。用户于2026-11-14再次提醒：GPT后续必须检查执行agent的新增/修改执行代码是否落实设计，不能只看汇报；修复及针对性小验证仍交执行agent，避免重复包揽验证。
12. **暂按串行协作**（用户于 2026-11-14 确认）：共享服务器目录由一个执行 agent 负责更新和执行，任务交接时再同步代码；运行中的工作树不 pull/切版本或改输入配置。既有运行不打断，新探索依队列串行推进；GPT 的设计文档经 reproduction 交接。

13. **职责最新调整（2026-11-14 23:22，用户认可后执行）**：GPT负责先写核心实验/统计逻辑，包括资格、时序、clean配对、分母和关键证据导出，并继续设计讨论及审阅；执行agent负责服务器适配、针对性小验证、正式执行和反馈。涉及实验含义的修改先讨论，普通环境适配可自行处理并记录。此条更新第11条的代码实现分工；仍不重复包揽大规模验证，不操作正在运行的工作树。

## Review 流程

- 看板列出“需要 review”的任务、审查对象和重点；日志说明**为什么改、改了哪些**。
- Reviewer 先读 `log.md`，再读看板给出的代码/文档路径，最后把结论写回看板“Review 结论”和 `log.md`。
- Reviewer 不直接改 `consensus.md`；共识变更需用户确认。

## 快速开始

- 最近发生了什么：`log.md` 末尾
- 长报告：`handoff/`
