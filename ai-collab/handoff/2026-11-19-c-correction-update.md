# C 纠错后训练与 UPDATE：实现和执行交接

用户已批准实施：C纠错三个原种子（42/1234/2026），UPDATE先2026，原50k数据，各50epoch。新增“未做纠错后训练的原C接收污染向量”的功能检验。完整设计、loss、矩阵、命令见 [README](../../tools/c_update/README.md)。

## 交付范围

- `tools/c_update/protocol.py/prepare.py`：原始训练数据和权重SHA、B注错配置核对、一次性dev/test清单、固定选点。
- `runtime.py/train_model.py/losses.py`：free hidden BPTT、新可算位置5%有效batch×50%位置、当前模型反事实源、第二层UPDATE监督、正确性/对齐/清零、四次50epoch训练与恢复。
- `evaluate.py/functional_probe.py`：节点值/四属性、长期续算、三个时点、u/q联合污染、持续污染、噪声、增加新下游计算、原C接收功能检验。前向内没有门控、没有冻结位置。
- `summarize.py/compare.py/summarize_training.py`：实际剂量、各分母、条件恢复、共同资格配对端点、读出与使用分开。跨模型源通过率不同不能藏掉。
- `verify_server.py/tests/execute.py`：一次针对性小验证、独立smoke、串行训练、固定正式评估。

## 执行agent职责

1. **分阶段确定唯一队列负责人**：Agent C负责prepare、smoke和四次训练；训练完成并明确交接后，Agent B负责五个原权重及四份final的正式评估、统一表和案例整理。Agent B不是仅评估模型B。GPT负责设计、执行适配审阅和结论讨论。确认现有工作空闲后再同步；训练运行期间不pull/换代码，B不同时启动GPU评估或改运行树。
2. 运行prepare、smoke。技术核对重点：source age=depth+1/recipient forward index=depth；原teacher目标一致；第二层hook不改变forward；对齐项只罚错的一侧；原hidden在新下游追加时未重置；UPDATE仍始终连续。
3. 特别交原C功能探针：源读成错值的数量、q受影响的数量、q是否等于错父值代入结果、对照组、未符合资格的分母。原C也可能自然恢复，不能把“未传播”直接写成向量无效。
4. smoke技术正确后自行进入四次正式50epoch训练。**不因小评测一般停止，不新增普通续训，不重训A/B，不扩UPDATE种子**。数值/接口错误停下记录；改变实验含义先讨论。
5. Agent C负责epoch1/3/5/10/15/20…50自动小评测及原C功能探针；交付唯一plan路径/SHA、运行提交/代码hash、四份final路径/SHA、训练曲线、实际剂量、阶段评估和异常记录。确认训练队列退出后在board/log交给Agent B，不自行重复启动正式evaluate。
6. Agent B接收上述产物，沿用同一plan运行`execute.py --phase evaluate`，不重生成数据、不重复阶段自动小评测。formal test不用于选模。交统一比较表、具体轨迹、可支持/暂不支持的结论，重点区分读出正确与下游实际使用、同值来源控制、更新定位/实际执行和不同分母。程序已提供共同资格端点比较；条件恢复率仍按实际受损集合另列。
7. 普通环境适配可修并记录，不能静默换数据、改源向量年龄、改变监督规则或选择性补图。大权重/raw留tmp，小报告/图表/实际命令/失败记录/源码hash进docs与board/log。GPT审阅交付。

## 重要解释边界

- 当前实现保持4层并监督已有REGRET头；不是“先单独前向定位，再前向计算”，也不是硬mask控制执行。
- 所谓执行对齐是末层VALUE是否变化，与第二层计划对齐；仍不能凭这个指标断言内部只在相应位置计算。
- UPDATE使用同步局部目标：错父值若仍在输入，子节点本轮标签也可暂时不同于原题最终真值；下一轮父值恢复再修正。correction路则沿用原teacher进度。这是两套已批准训练配方，比较结果不能只归因于一个额外头。
- 前向输入中的REGRET/MODIFICATION不回灌为离散字段；连续hidden原样递归，最后UPDATE FALSE仅是读出监督。
- 训练污染源读出通过后才替换，但不按下游传播成功筛训练数据。另设未做后训练原C接收检查；当前权重→原C属于跨权重表示迁移，必须看同值/原图来源对照。
- 旧报告不能替代新清单评估；依旧不把模型自然读出错误、人工注入错误、潜在表示变化混成同一类。
