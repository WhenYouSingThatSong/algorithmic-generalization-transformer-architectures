## 1. 两个量

对每个结果位置、每一轮，记相邻两轮隐藏态的变化：

- `1 − cos(h_t, h_{t+1})`：方向变化；
- `‖h_{t+1} − h_t‖ / ‖h_t‖`（下称 rel_norm）：含缩放的相对变化，余弦看不到纯缩放。

`lead = depth − t`。lead = 0 是"本轮该算的位置"，lead ≥ 1 是"还没轮到的位置"。

## 4. 读数

### 4.1 不冻结时，未到轮次的位置每轮几乎不动

第 5 轮 lead≥1 的 `1−cos` 在 0.0004–0.0037，rel_norm 在 0.04–0.07；第 1 轮之后基本稳定在这个量级（见 json 的 by_round_lead）。

而第 0 轮时所有位置的 `1−cos` 都在 0.40 左右。也就是说，**把输入嵌入变成"计算用"的表示几乎全发生在第 0 轮；此后未到轮次的位置基本停住。**

### 4.2 但前向每轮仍"想"把它们改动约 0.40

冻结条件里，被钉住位置的记录值是前向试图施加的变动（≈0.40），而实际生效为零。这说明：**未到轮次的位置停在一个离"原始嵌入"很远的不动点上**——它们不动，是因为每轮重算出来的结果与上一轮几乎相同，不是因为没有被重算。

### 4.3 因此冻结这一干预实际做的是什么

按实现，冻结把「depth > t」的位置每轮退回**上一轮的值**；由于第 0 轮就把它们退回了 `h_0`，**这些位置在整个运行中一直停在那个初始状态**（raw embedding）。所以冻结的代价主要来自"用初始状态代替稳定后的表示"，而不是"少了几轮微小更新"。

这一点必须在使用这组数字时写明，否则容易把冻结的退化读成"模型需要逐轮累积预计算"。

### 4.5 冻结到底做了什么（用单个节点说明）

取一个 **depth = 5** 的节点 u，它必须在第 5 轮输出正确值。

| 轮次 | 不冻结 | 冻结 g=0 | 冻结 g=1 |
|---|---|---|---|
| t=0 | u 的隐藏态被前向大幅改写 | 改写后又被退回原值，停在原始 token 嵌入 | 退回原值 |
| t=1…3 | 每轮微调（变化量级 0.001） | 继续退回 | 继续退回 |
| t=4 | 微调 | 继续退回 | **从这一轮起允许更新** |
| t=5 | 输出正确值 | 输出正确值，但状态只被更新过 1 次 | 状态被更新过 2 次 |

所以 **g 的含义是「节点在自己的轮次之前，能提前几轮开始被更新」**。

按实现，冻结把「depth > t + g」的位置每轮退回**上一轮的值**；由于第 0 轮就退回了 `h_0`，这些位置在整段运行里一直停在 `h_0`，即**原始 token 嵌入**，而不是某个算好的中间状态。

### 4.6 一处尚未解释的不一致，以及一个可能原因（未验证；**已被 §4.10 取代**）

两组测量放在一起对不上：

- **更新幅度**：第 0 轮之后，未到轮次的位置每轮几乎不动（第 5 轮 lead≥1 的 `1−cos` 只有 0.001 量级）。
- **冻结扫描**：如果状态真的在第 0 轮就稳定，那么 g=1 应当基本追平基线；实测 g=1 只从 0.517 回到 0.643，要到 g=4 才到 0.896。

**一个可能的原因（尚未验证）**：冻结不是只影响被冻结的那个位置。注意力每轮让所有位置互相读取，被钉在原始嵌入的深节点会成为**其他所有位置的输入**。若如此，精度下降主要来自“上下文被污染”，而不是“被冻结的位置自己缺了更新”。

**这个可能原因若成立，则本节的精度数字不能用来证明“模型使用了跨轮的预计算通道”**——它把两件事混在了一起。

**怎么判定**：只冻结极少数位置（例如每张图随机钉 3 个深节点），然后单独看**没有被钉住**的节点精度是否下降。下降说明以污染为主、现有冻结实验需要重做；不下降说明以“被冻结节点自身缺更新”为主、现有读数可用。**该测试尚未执行。**

### 4.7 附带发现

冻结后，**本轮该算的位置**（lead=0）的变动从 0.09 涨到 0.44——钉住未到轮次的位置，会显著改变已到轮次位置的计算动态。这与 §4.6 的“污染”猜测方向一致，但同样**不能作为证据**。

## 4.8 已经算出的节点还会不会被更新（研究者 2026-11-28 提问）

不冻结条件下，按 `lead = depth − t` 统计每轮变化（三个种子一致）：

| lead | 1−cos | rel_norm | 说明 |
|---|---:|---:|---|
| 0 | 0.09–0.11 | 0.42–0.47 | 算出来的当轮，大幅改写 |
| **−1** | **0.026–0.034** | **0.24–0.26** | **下一轮还有一次明显更新** |
| −2 | 0.0017–0.0032 | 0.06–0.10 | 迅速变小 |
| −3 | 0.0002–0.0005 | 0.02–0.03 | 基本稳定 |
| ≤ −4 | 约 0.0001 | 0.01–0.02 | 几乎不动 |

所以：**节点算出来之后，下一轮还会被明显改写一次，之后基本冻结。** 各冻结条件下 `lead=−1` 的读数与不冻结相近（0.02–0.04），因为冻结只钉「还没轮到的位置」，已算出的位置从不被冻结。

## 4.9 一个尚未执行的对照：加大总轮次

本文件的运行固定 `L = max_depth + 1 = 19` 轮，精度取**最后一轮**的读出。目前只扫过**提前量 g**（让位置在自己轮次之前多更新几轮），**没有**加大**总轮次 L**（让它在自己轮次之后多几轮修正机会）。

两者补的不是一回事：冻结损害的是"轮次之前"的更新，而加大 L 提供的是"轮次之后"的修正。若"冻结 + 若干额外轮次"能回到基线附近，说明冻结的损害只是总计算量不足，而不是缺少轮次之间的预计算。**该对照尚未执行。**

## 4.10 冻结阶梯：旧冻结的损害全部来自第 0 轮那次变换

按[阶梯设计](vector-difference-and-freeze-ablation-design.md)执行。条件名不复用字母，避免与模型名冲突。规模：**32 题 × 3 种子**（每条件 4,096 个结果位置）；`rel_l2² = radial² + tangential²` 自检误差约 4×10⁻⁷。

### 结论

1. **`hold_unreached_from1` ≈ `baseline`**（s42 与 s2026 完全一致）。**旧冻结的全部损害来自“第 0 轮那次变换没有发生”。**
2. **第 0 轮之后再钉住没有影响**。也就是说，未到轮次的位置在第 1 轮之后的逐轮更新，对最终结果没有可测的作用。
3. **算完之后的那次更新基本不必要**（s42 完全不掉；s1234 掉 0.039、s2026 掉 0.010，允许 1–2 轮即恢复）。
4. **多给 8 轮没有帮助**，所以旧冻结的退化不是“算得不够久”。

### 这取代了 §4.6 的解读

§4.6 曾提出“注意力跨位置污染”作为 `hold_unreached_from0` 掉分的可能原因。现在不需要这个假设：`from0` 与 `from1` 的唯一差别就是第 0 轮是否施加变换，而 `from1` 完全恢复。

### 对原假设的意义（只陈述可测的部分）

- 跨轮载体**确实被用到**：只保留第 0 轮的写入、之后不再更新，仍与基线相同。
- **“每轮持续更新”这一步没有被用到**。
- 更准确的描述：信息在**第 0 轮那次前向**里写进隐藏态，此后基本原样携带，而不是逐轮累积。
- 这**不支持**“隐藏态在未到轮次的位置上逐轮演化出结果”这一形式；h₁ 里已经含有什么、以什么形式编码，本轮没有测。

## 5. 限制

1. 更新幅度的样本只有 **8 题**（每种子 13,312 个位置—轮次对），种子间趋势一致但绝对值未做置信区间。
2. `1 − cos` 只看方向，rel_norm 只看范数比例；两者都不能说明"在算"。
3. 冻结是**分布外**干预，且如上所述与"退回初始状态"混在一起。
4. 精度部分只有 **8 题**（1,024 个结果位置）。200 题的冻结扫描两次尝试都在共享 GPU 上 OOM（一次是启动时卡被占、一次是运行中其他用户占用了同一张卡），**尚未取得**；因此这里的绝对精度可能随样本变化，但趋势在三个种子上一致。
