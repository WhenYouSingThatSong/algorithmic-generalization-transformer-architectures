# 跨轮信道这条线的讨论过程（原始记录）

- 记录时间：2026-11-28 整理
- 对应：[PLAN-010](../../../PLAN-010/README.md)、主文档 EXPERIMENT-075
- 说明：本文按时间顺序保留讨论与实现过程，包括**被撤回的做法、出过的判断错误、以及目前仍未解决的点**。结论性的文件是另外三份（[探针设计](probe-and-channel-shutdown-design.md)、[探针结果](probe-and-channel-shutdown-results.md)、[冻结与更新幅度](freeze-and-update-magnitude.md)）。

## 1. 研究者的判断（2026-11-27）

离散与连续循环模型最本质的差别在**跨轮的信息通道**：离散侧每轮重新嵌入 token，轮与轮之间只传递已写回的离散字段；连续侧每轮每位置接收上一轮的完整向量，而监督只约束读出、不约束隐藏向量。因此机制的落脚点应在"隐藏向量在监督触及不到的地方形成了什么机制"，且这种机制因缺少监督而有较大随机性，需要多种子与充分训练才看得出。

同轮还提出：可以做一个"不允许未到轮次的向量更新"的小验证，看性能是否退化。

## 2. 实现前的代码核实（2026-11-28）

- `model.py:476` 的 `value_avail_pos = (depth ≤ 目标)`：只在这些位置把 VALUE 换成标签，其余保留输入的 EMPTY。
- `model.py:893`：C 每轮 `label = batch_ext[loop + 1]`，即"depth ≤ loop 填真值"。
- 该轮损失对**展平整序列**求 CE，无位置掩码。
- 结论：**两个家族的监督结构相同**（可算处读真值、未到轮次读 EMPTY）；差别在跨轮载体与带宽。

这条事实修正了研究者的初始表述（"监督非常不充分"），改为"监督只约束读出、不约束隐藏向量；且要求未到轮次处输出 EMPTY，等于要求模型把已知内容收进隐藏态"。研究者认可。

## 3. PLAN-010 建立（2026-11-28）

第一步两件事：D 多种子从头训练（普通纠错 + 多时间点纠错）；在现有 C 上做小验证与初步机制分析。训练预算定为 3 个种子（沿用原三个）、200 周期、每 50 周期保留 `last` 与该阶段验证最好的三份；先 4 个 run 并行。

## 4. 探针的实现与两轮读错的数

- 设计：探针必须读**产出 EMPTY 读出的那些隐藏态**（`h_{t+1}[u]`，t < depth(u)），否则与"当场算出来"混淆。
- **第一次读错**：4 题上 train acc = 1.0、val ≈ 随机，被读作"没有信号"。实际是**过拟合**。→ 之后所有探针输出都同时给 train acc。
- **第二次读错**：200 题上 train acc 只有 0.19–0.22、val ≈ 随机。这次是**欠拟合**，不能读作"信息不存在"。→ H1 至今**未判定**。
- 实现中修的错误：① 单父节点写成 `x_a = x_b`（无运算符）被解析器跳过，导致父变量缺值；② 新版 sklearn 不再接受 `multi_class`。

## 5. 被撤回的两个变体

原先还做了 `reembed`（每轮重新嵌入原始输入）与 `rewrite`（把解码值写回 token 再嵌入）。研究者指出这两个在当前情形下会混淆视听。核实后同意并撤回，理由比"混淆"更硬：

- `rewrite` 写回的内容大多是 EMPTY，模型面对"VARIABLE + 已填值"的输入仍输出 EMPTY，**它没有构成离散通道**，与 `reembed` 实质同一件事；
- 两者都是分布外干预，且不能与 A/B 的条件相比。

原始数字仍在 `json/probe.json`，标注为不作结论。

## 6. 冻结 + 更新幅度（研究者提出扩展）

研究者要求：① 记录里只保留冻结；② 冻结再加"允许提前 g 轮"的扫描；③ 用 `1 − cos` 表示每轮更新幅度，在小规模（整张图都算）上按轮次与位置看。

实现后出的第一版有个混杂：按 `lead = depth − t` 的边缘趋势显示"lead 越大变化越大"，但大 lead 只可能出现在早期轮次。加入（轮次 × lead）交叉表后，边缘趋势被证伪：**同一轮次内，未到轮次的位置几乎不动（`1−cos` 约 0.001），只有本轮该算的位置有明显变化（约 0.09）。**

随后研究者要求更新幅度要在**不冻结与各冻结条件**下都测，于是把条件参数化（none / freeze0…freeze4）。

## 7. 一个解释不了的矛盾，与一个未验证的猜想

- 更新幅度显示第 0 轮之后状态就停住；
- 冻结扫描却显示要允许 g=4 才接近基线（g=1 只从 0.517 回到 0.643）。

当时的猜想是"注意力跨位置污染"：被钉住的深节点会成为其他位置的输入。**该猜想未验证**，已在记录中标注。

## 8. 研究者指出关键细节，改变了整个解读（2026-11-28）

> 正常运行时，距计算时点还很远的节点，最大的变化发生在第一次前向。此后到正式求值之前，它们平均每轮的向量变化小得多。这个是不是也值得消融一下，如果第一轮不冻结呢对比。

这条直接指出：旧冻结把位置钉在 `h_0`，**阻断的是第 0 轮那次大变换**，而不是"后续预计算"。于是补了阶梯 A–G。

## 9. 阶梯结果（3 种子，8 题）

| 条件 | s42 | s1234 | s2026 |
|---|---:|---:|---:|
| A 不冻结 | 1.000 | 0.980 | 1.000 |
| B 从第 0 轮起冻结 | 0.517 | 0.796 | 0.433 |
| **C 第 0 轮不冻结** | **1.000** | **0.979** | **1.000** |
| D2 / D3 更晚才冻结 | 1.000 | 0.980 | 1.000 |
| E 算完不许更新 | 1.000 | 0.950 | 0.994 |
| F1 / F2 算完允许 1–2 轮 | 1.000 | 0.978 | 1.000 |
| G / A8 多 8 轮 | 0.993 / 0.997 | 0.981 / 0.977 | 0.999 / 1.000 |

**解读**：旧冻结的损害全部来自第 0 轮那次变换；第 1 轮之后的逐轮更新对最终结果没有可测作用；算完那次更新基本不必要；多给轮次没有帮助。**§7 的污染猜想因此不再需要**。

对原假设的意义（只陈述可测部分）：跨轮载体确实被用到（完全移除则模型输出 EMPTY），但"每轮持续更新"这一步没有被用到；更准确的描述是"信息在第 0 轮写进隐藏态，此后原样携带"。H1（h₁ 里是否已含该节点的结果）仍未判定。
