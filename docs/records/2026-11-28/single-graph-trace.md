# 单张图的完整计算过程追踪（16 与 32 节点），与"完全冻结"条件

- 日期：2026-11-28
- 计划：[PLAN-010](../../../PLAN-010/README.md)；主文档记录单元 EXPERIMENT-075
- 代码：[tools/c_channel/trace_one_graph.py](../../../tools/c_channel/trace_one_graph.py)、[tools/c_channel/ablation.py](../../../tools/c_channel/ablation.py)
- 数据：`json/trace/trace_16nodes_seed42.csv`（80 行，逐轮逐位置）、`json/ablation_freezeall.json`

## 1. 为什么要单图追踪

研究者提出：结合任务性质，应当分开回答两件事——**没到算它的时候（父节点还不完备）它更新了什么信息**、**算完了又更新了什么信息**。并追问这两个部分是否正好对应此前观察到的两处较大变化（第一次前向、以及算完之后那次）。

## 2. 图与设置

- 权重：旧 C0 s42 的 e143。
- 图：**生成**一张 16 个节点、最大深度 4 的图（用本仓库的 `generate_dataset`）。**节点数与训练分布不同**（训练是 32 节点），仅用于过程观察。
- 标签复现校验：从 token 序列解析后按"父值之和 mod 23"重算，16 个结果位置**全部吻合、0 失败**。
- 轮数：`max_depth + 1 = 5`（t = 0…4）。记录 5 × 16 = **80 条**（轮次 × 位置）。

## 3. 三个阶段的变化幅度

| 阶段 | 样本 | `1−cos` | `norm_ratio` | `rel_l2` |
|---|---:|---:|---:|---:|
| 未到轮次（depth > t） | 22 | 0.1858 | 1.527 | 0.877 |
| 本轮该算（depth == t） | 16 | 0.2531 | 1.260 | 0.922 |
| 已算完（depth < t） | 42 | 0.0140 | 0.993 | 0.123 |

粗看"未到轮次"也很大，但那是被第 0 轮拉高的。分轮拆开后（下表）才能看到真实结构。

## 4. 逐轮：本轮该算的位置

| t | 位置数 | 读出正确 | `1−cos` | `rel_l2` |
|---:|---:|---:|---:|---:|
| 0 | 6 | 6/6 | **0.459** | **1.639** |
| 1 | 3 | 3/3 | 0.138 | 0.506 |
| 2 | 3 | 3/3 | 0.129 | 0.492 |
| 3 | 3 | 3/3 | 0.126 | 0.486 |
| 4 | 1 | 1/1 | 0.120 | 0.476 |

第 0 轮特别大（`norm_ratio` 约 2.1–2.35，**模长翻倍**），因为那一轮同时发生输入嵌入的重新编码。

## 5. 未到轮次（depth > t）：按"父节点已完备数"分组

| t | 父节点完备 | n | `1−cos` | `norm_ratio` | `rel_l2` |
|---:|---|---:|---:|---:|---:|
| 0 | 0/1、0/2、1/3、2/2、2/3、3/3 | 10 | **0.35–0.43** | 2.09–2.35 | 1.63–1.96 |
| 1 | 1/1、1/2、2/3、3/3 | 7 | **0.006–0.016** | 0.97–1.02 | 0.11–0.18 |
| 2 | 2/2、2/3、3/3 | 4 | 0.002–0.005 | 0.92–0.97 | 0.06–0.13 |
| 3 | 3/3 | 1 | 0.001 | 0.935 | 0.080 |

**关键**：第 0 轮里，**父节点一个都没完备（0/1、0/2）的位置，和父节点已全完备（3/3）的位置，变化幅度一样大**（0.43 对 0.40，模长都翻倍）。所以第 0 轮那次大更新**与父节点是否完备无关**，它是把输入重新编码一遍，不是"在算这个节点"。

第 1 轮之后，未到轮次的位置每轮只变化 0.001–0.016，**同样与父节点完备度无关**。

## 6. 已算完（depth < t）：按算完后第几轮

| 算完后第几轮 | n | `1−cos` | `norm_ratio` | `rel_l2` | 仍读对 |
|---:|---:|---:|---:|---:|---:|
| 1 | 15 | **0.0372** | 0.984 | 0.271 | 15/15 |
| 2 | 12 | 0.0023 | 0.997 | 0.069 | 12/12 |
| 3 | 9 | 0.0002 | 0.998 | 0.021 | 9/9 |
| 4 | 6 | 0.0001 | 0.999 | 0.015 | 6/6 |

**算完之后还有一次明显更新**（`1−cos` 0.037、`rel_l2` 0.27，以幅度调整为主，模长几乎不变），此后基本冻结（0.002 → 0.0001）。这几个位置在整个过程中读出始终正确。

## 7. 对研究者两个问题的回答

**"没到算它的时候它更新了什么信息"**：除了第 0 轮那次**与父节点完备度无关**的重新编码（模长翻倍、方向大幅变化），之后到它自己的轮次之前，每轮只变化 0.001–0.016。**没有观察到"父节点逐步完备 → 逐轮累积出结果"的痕迹。**

**"算完了它又更新了什么信息"**：还有一次以幅度调整为主的更新（`rel_l2` 0.27），然后停住；而且读出全程正确，**看不出这次更新对答案有作用**。

**"这两个部分是否正好对应那两处较大变化"**：**部分对应，但需要修正**。两处变化确实在时间上与这两个阶段重合，可是：
- 第 0 轮那一次**不是"未到轮次的位置在预计算"**——它对所有位置一视同仁，包括当轮就要算的 depth-0 位置（`1−cos` 0.459 与 0.40 同量级）；
- 因此把它当作"未到轮次阶段的更新"会误读。

## 8. "完全冻结"条件（研究者追问）

此前只有单向冻结（只钉未到轮次的、或只钉已算完的），**没有**同时钉住两侧。现已补三个条件（32 题 × 3 种子，`node_acc / graph_all`）：

| 条件 | 具体做法 | s42 | s1234 | s2026 |
|---|---|---|---:|---:|---:|
| `baseline` | 不冻结 | 0.9973 / 0.969 | 0.9797 / 0.250 | 1.0000 / 1.000 |
| `hold_all_from0` | 从第 0 轮起，两侧都钉住（只有输入嵌入，之后什么都不更新） | **0.4480 / 0** | **0.6421 / 0** | **0.3875 / 0** |
| `hold_all_from1` | 第 0 轮放行，之后两侧都钉住 | 0.9973 / 0.969 | **0.9324 / 0.031** | **0.9897 / 0.656** |
| `hold_all_from1_extra8` | 同上，多跑 8 轮 | 0.9973 / 0.969 | 0.9324 / 0.031 | 0.9897 / 0.656 |

对照单向条件（同批 32 题）：`hold_unreached_from1` = 0.9973 / 0.9790 / 1.0000；`hold_computed_immediately` = 0.9973 / 0.9412 / 0.9902。

读数：
1. **完全冻结两侧、但保留第 0 轮**（`hold_all_from1`）：s42 完全不变，s1234 掉 0.047、s2026 掉 0.010。**所以"已算完位置的那次更新"对 s1234 / s2026 是有作用的**，不能笼统说"基本不必要"。
2. **连第 0 轮也不给**（`hold_all_from0`）：三份都掉到 0.39–0.64，整图全对率为 0。
3. **多给 8 轮仍然无帮助**（`*_extra8` 与不带完全相同）——因为两侧都钉住时没有可更新的对象。

## 9. 种子之间的差异（研究者追问）

同一批 32 题、同一条件 `baseline` 下：s42 `graph_all` 0.969、s2026 1.000、s1234 只有 0.250。

原因不是模型性质不同，而是**整图全对是乘性指标**：

- `node_acc`：0.9973 / 0.9797 / 1.0000，s1234 只落后 2 个百分点；
- 但一张图约 128 个结果位置，s1234 平均每图仍有 2–3 个位置错 → 整图全对率掉到 25%；
- s42 每图平均错约 0.35 个 → 整图全对率 97%。

所以**报 `graph_all` 时必须同时报 `node_acc`**，否则会把"差 2 个百分点"读成"差 4 倍"。

## 10. 局限

1. 单图追踪只用了 **s42 一份权重**、**一张生成的小图**，且节点数（16）不在训练分布（32）内。它说明的是"这张图上的过程"，不能直接外推到全部权重与全部图。
2. 第 5、6 节的分组样本很小（每组 1–10 个位置—轮次对），只作定性观察。
3. `hold_all_*` 的三个条件只跑了 32 题。

## 12. 逐轮逐位置的数据文件与列定义

`json/trace/trace_16nodes_seed42.csv`：**5 轮 × 16 位置 = 80 行**，一行 = 某一轮对某一位置的记录。

| 列 | 含义 |
|---|---|
| `t` | 轮次（0…4） |
| `var` / `pos` | 变量编号 / 该变量在序列中的位置 |
| `depth` | 该位置的真深度 |
| `phase` | `pre` = 未到轮次；`at` = 本轮该算；`post` = 已算完 |
| `parents_total` / `parents_available` | 父节点总数 / 本轮已可用的父节点数（叶子恒可用） |
| `parents_desc` | 各父节点的 `变量@深度` |
| `parents_readable` | 本轮从**各父节点位置**读出的 VALUE |
| `label_syntax/variable/operation/value` | 该位置的标签四字段 |
| `read_syntax/variable/operation/value` | 模型在该轮的读出四字段 |
| `value_correct` 与 `{syntax,variable,operation,value}_correct` | 各字段是否与标签一致 |
| `norm_before` / `norm_after` | 本轮前 / 后的隐藏向量模长 |
| `one_minus_cos` | `1 − cos(h_t, h_{t+1})`，方向变化 |
| `norm_ratio` | `‖h_{t+1}‖ / ‖h_t‖`，模长比 |
| `rel_l2` | `‖h_{t+1} − h_t‖ / ‖h_t‖`，方向与模长合计 |
| `radial` | 沿原方向的分量（有符号，相对） |
| `tangential` | 垂直分量（相对）；恒有 `rel_l2² = radial² + tangential²` |

**可直接用于画图的建议**：横轴取 `t`，每个位置一条线；用 `phase` 上色；`one_minus_cos` / `rel_l2` 画变化幅度，`read_value` 与 `label_value` 画读出轨迹，`parents_available/parents_total` 画父节点完备度。

## 13. 训练分布内的对照：32 节点、depth 4

16 节点那张是**生成**的，节点数不在训练分布（训练为 32 节点）。为排除这一点，另取**训练集第 5 题**（32 节点、最大深度 4，完全在分布内）做同样的追踪：32 个结果位置、5 轮、160 行、标签复现 0 失败。数据 `json/trace/trace_train4_none_seed42.csv`。

### 13.1 两者对照

| 指标 | 16 节点（生成） | 32 节点（训练集） |
|---|---|---|
| 第 0 轮"本轮该算"的 `1−cos` | 0.459 | 0.482 |
| t=1 / 2 / 3 / 4 的 `1−cos` | 0.138 / 0.129 / 0.126 / 0.120 | 0.118 / 0.118 / 0.111 / 0.114 |
| 第 0 轮 · 父节点 0 完备 | n=2，`1−cos` 0.417，`norm_ratio` 2.33 | n=8，`1−cos` 0.404，`norm_ratio` 2.23 |
| 第 0 轮 · 父节点全完备 | n=3，`1−cos` 0.397，`norm_ratio` 2.13 | n=6，`1−cos` 0.397，`norm_ratio` 2.10 |
| 算完后第 1 / 2 / 3 / 4 轮 | 0.0372 / 0.0023 / 0.0002 / 0.0001 | 0.0319 / 0.0021 / 0.0001 / 0.0001 |
| 首次读对轮次 == depth 的位置 | 16/16 | **32/32** |
| `pre` 阶段 VALUE 读对 | 0/22 | 0/67 |
| `at` 阶段 VALUE 读对 | 16/16 | 32/32 |
| `post` 阶段 VALUE 读对 | 42/42 | 61/61 |

**结论：两项主要观察在两种规模上都成立，且数值接近。**

1. 第 0 轮里"父节点一个都没有"与"父节点全都有"的位置，变化幅度一样（0.40–0.42，模长都约翻倍）——再次说明那次更新与父节点完备度无关。
2. 已算完的位置在下一轮还有一次明显更新（0.032–0.037），之后掉到 0.002 以下。
3. 全部 48 个位置（16 + 32）都在**自己 depth 那一轮**首次读对，之后读出不再变。

### 13.2 这点为什么值得记

此前只追踪了一张 16 节点的生成图，用它说明"过程长什么样"存在一个明显的外部效度疑问：节点数不在分布内，模型可能表现出不同的过程。现在 32 节点（分布内）给出同样的结构与接近的数值，这个疑问可以排除。

## 14. 初始条件干预的逐步追踪（对应 EXPERIMENT-073 / 074）

此前做过的"随机初始状态"与"整图无正确值"两个实验（EXPERIMENT-073「第一次前向之前预填结果格」、EXPERIMENT-074「整图无正确值时的恢复」）都只在汇总层面留下读数。此处对**同一张 32 节点、depth 4 的训练集样本**做逐步追踪，输入条件四种，三个种子各一遍。

### 14.1 输入条件

预填只改结果格里存放的数值，题面常数、算式、变量名与对变量的引用全部保留。

| 条件 | 做法 |
|---|---|
| `none` | 原题，结果格全空（对照） |
| `random` | 按比例均匀随机预填（本轮比例为 1.0，即全部结果格都填；可能碰巧正确） |
| `all_wrong` | 按拓扑顺序为每个结果格选一个**既不等于真值、也不等于父值当前推出的数**（父值不足时只要求不等于真值） |
| `correct` | 全部结果格预填**真值** |

### 14.2 结果：VALUE 在"自己的轮次"与"之后"读对的比例

| 种子 | 条件 | 本轮该算（32 个） | 已算完（61 个） |
|---|---|---:|---:|
| 42 | `none` | **32/32** | **61/61** |
| 42 | `random` | 5/32 | 24/61 |
| 42 | `all_wrong` | 13/32 | 43/61 |
| 42 | `correct` | **14/32** | 43/61 |
| 1234 | `none` | **32/32** | **61/61** |
| 1234 | `random` | 17/32 | 48/61 |
| 1234 | `all_wrong` | 11/32 | 44/61 |
| 1234 | `correct` | **12/32** | 42/61 |
| 2026 | `none` | **32/32** | **61/61** |
| 2026 | `random` | 4/32 | 19/61 |
| 2026 | `all_wrong` | 2/32 | 15/61 |
| 2026 | `correct` | **19/32** | 45/61 |

### 14.3 读数

1. **全空时三份权重都是满分**（32/32、61/61）。
2. **任何预填都大幅降低读出正确率**，三个种子一致。
3. **把真值直接预填进去也没能保住**：`correct` 条件在自己轮次只读到 12–19/32，并不优于 `all_wrong`（2–13/32）。也就是说，**模型既没有"读出已有值"，也没有"保留已有值"**——它按自己的方式重算，覆盖掉了正确初始值。
4. 这一现象与 EXPERIMENT-073 在汇总层面的记录一致（"起初正确……多数位置出现过正确值被改坏"）。

### 14.4 一个必须写明的混淆

**预填对 B 是分布内的，对 C 不是。**

- B 的训练配方本身就会在结果位置写入错误数值（`recorrection_args`，策略 `last`，掩码是"本轮新可算、输入仍是 EMPTY"的位置），所以"结果格里有值"是 B 见过的情况；
- C 的训练全程结果格都是 EMPTY（`compute_batch_loss_nointerm` 的输入来自 `batch`），**从未见过有值的结果格**。

因此上面第 3 条的"覆盖掉正确初始值"，可能一部分来自**分布外输入下的行为退化**，而不完全是"模型有重算的倾向"。要分开这两者，需要：给 C 做一次同样的污染式后训练（即 PLAN-010 的 D），再在同题同位置上比较。**在这一步之前，不宜把本条写成机制结论。**

### 14.5 数据

`json/trace/` 下 12 份 CSV（4 条件 × 3 种子）加 1 份 16 节点图，列与 §12 相同，另有两列：`prefilled`（该格是否被预填）、`prefill_value`（预填的数值，未预填为 −1）。
