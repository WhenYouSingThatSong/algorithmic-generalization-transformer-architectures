# 项目现状总览：权重、实验、结果与尚未解决的问题

更新：2026-11-16。核对分支 `reproduction`，资料基线 `a2e9eb8`；本次同步未发现新的远端实验提交。最新实验仍是11月15日已交付的结果，不能把本文件日期理解为新增了一批实验。

## 摘要

目前已完成**A′/B同架构的主要注错实验、三个可用C₀种子的能力诊断，以及s2026上的两批监督后训练小比较**。B机制还没有完全解释清楚；C+已有探索权重，但尚未开展三种子正式比较。

- **B会覆盖已有错值，A′通常保留已有值。** B也会先把错误传到下游，再逐轮恢复；目标修回不保证整条链恢复，已经发现持续失败案例。
- **C₀通常能先算对，继续循环后会漂移。** 变量名读出常比数值更早出错，但尚不能说前者导致了后者。
- **延长保持监督有明确收益。** 单种子六档统一评估中，hold把长期节点数值正确率从79.60%提高到97.72%；四属性同时正确率仅34.45%，漂移没有解决。
- **额外语义注错减少了部分初始错误传播，但没有显示更快恢复。** 持续写入错误父状态后，首轮优势消退；还出现“目标数值一直读对，下游仍延迟出错”的情况。
- **历史离散raw评估存在已确认的实现bug。** 原始评估器把训练中禁用、无任务监督的两个辅助字段预测重新回灌，改变下一轮输入；clean恢复训练时的固定FALSE处理。该bug已确认，论文具体作图是否经过此路径另需运行证据。

## 2. 任务和模型到底在做什么

论文为 *Unlocking Out-of-Distribution Generalization in Transformers via Recursive Latent Space Reasoning*。当前主实验使用有向无环依赖图上的加法，结果取模23。例如 `r=4，u=r+9=13，q=u+2=15`。

模型每轮处理整道题的序列，对所有位置输出隐藏状态；不是每轮只生成一个token。依赖传播靠多轮更新完成。每个位置可以读出六个字段：语法类型、变量名、运算类型、数值，以及REGRET、MODIFICATION两个辅助字段。

- **A/A′：离散、有中间状态监督、无专门注错训练。** 下一轮接收解码后的离散状态。
- **B：离散、有中间状态监督、有注错训练。** 与A′的主体架构、fast训练路径对齐。
- **C₀：连续、有中间状态监督。** 对应当前复现的M4/nointerm路径，下一轮直接接收隐藏向量；读出的字段用于监督和观察，不作为离散状态回灌。
- **C+：连续模型的纠错/稳定性改进方向。** 当前已有后训练探索权重，但尚未定下正式方法。

主要A′/B/C₀都是4层、16个注意力头、隐藏维度384。历史A另有2层或维度256版本，不能与B直接当作只差纠错训练的对照。

这里的OOD主要指相对训练配置的规模或依赖深度外推，运算规则仍是模23加法；不能因此声称已经验证了任意算法或新任务泛化。超过128节点的任务尚不在本轮实验范围。

### 当前主要指标

1. **节点数值正确率**：变量定义节点的VALUE正确比例，包括叶变量、内部节点、最终节点；排除常数、运算符和PAD。
2. **节点四属性同时正确率**：同一节点的语法、变量名、运算、数值四项全部正确才算对。不是四项准确率的平均。
3. 以上优先逐图等权，节点加权和分子/分母作为补充；整图全对率用于补充完成情况，不独占能力评价。
4. 注错实验分别报告实际注错、首次输出修回、窗口内受损、最后两轮恢复、曾恢复后又错，以及未受损节点被带坏的情况。
5. “最后两轮正确”只描述给定H，不等于永久稳定。早期尚未该算出的EMPTY不能直接算新增错误；需与同轮不干预分支配对。恢复率的分母是实际受损且可观察的集合，零受损记NA。

**不同模型受损集合可以不同。** 因此不能只比较各自的条件恢复率；还要一起看相同目标/图上的损伤、最终正确率和直接修回。H64与D+64、首轮与最终、节点与整图、逐图等权与原始计数都不能混成一列。

### raw/clean：原始离散评估器的辅助字段回灌bug

**已确认这是原始公开仓库离散评估器的实现bug，不能只表述成两种同样合理的评估口径。** 11月16日复核了作者原始提交`52dd950`、当前实现及本地论文v1；完整证据见[raw专项核查](raw-aux-bug-review.md)。

| 环节 | 实际行为 | 含义 |
|---|---|---|
| 论文§4机制3、附录B.3公式(7) | 定义syntax/variable/operation/value四种属性；B.4纠错污染VALUE | 没有将REGRET/MODIFICATION定义为该方法的工作状态或纠错信号 |
| 原始数据、训练 | tokenizer把两个辅助字段设为FALSE；loss权重`[1,1,1,1,0,0]`；fast teacher状态只更新VALUE | 两个辅助输出没有任务损失监督，输入保持FALSE |
| 原始模型内续算/验证 | teacher及自由续算分支都显式将两字段重置FALSE，注释为disable；纠错regret分支未启用 | 禁用是实现中的明确行为，不只是论文没提 |
| 原始独立评估器，即历史raw | 对全部六个输出做argmax，全部放入下一轮，未重置两个辅助字段 | 意外启用了训练/验证禁用的反馈，改变实际计算 |
| clean | 仍预测六字段，但下一轮前把两辅助字段固定FALSE | 恢复公开训练/模型内续算的处理，不改答案、不回灌正确VALUE、不重训模型 |

仓库中确实存在两字段的词表、嵌入、输出头和预留分支，所以不能说“代码完全没有它们”。准确表述是：**公开使用的训练路径未将它们作为动态状态学习或启用，评估器却将其预测作为动态状态回灌。**

例如某节点VALUE已经正确读为4，但未经任务监督的REGRET头输出TRUE。raw下一轮会使用`Embedding(REGRET=TRUE)`，而训练路径用的是`Embedding(REGRET=FALSE)`；六个字段嵌入求和，差值直接改变Transformer输入，可能让后续值算错。评估只统计前四字段，**并不能**消除后两字段对计算的影响。这个bug是反馈逻辑错误，不只是多算了两项评分。

历史A-M5在N128的raw跨三个种子约0%、9.8%、88.1%，clean均约99.9%–100%。无纠错A-L4fast也能在raw下表现很好，说明不同权重对该缺陷的敏感度不同；“raw好”不能单独证明自纠错。当前B机制实验使用固定辅助字段的clean路径。

当前仓库的`experiments/evaluation/metric_utils.py`离散默认路径仍可见该回灌行为；新的B机制runner另行强制FALSE。本次只核查并更正文档，没有静默修改旧评估入口或重跑历史实验。修复默认入口需显式保留legacy raw用于追溯，避免新旧结果同名混用。

**两个边界分开说：**①原始公开代码的这个bug及我们的raw/clean性能差异已有证据；②作者Figure 4实际用的运行版本/路径还未取得，不能由①直接断定整张论文图或全部结论由此造成。另，文件名中的raw也可能仅指原始数据导出，不能据此判定C的连续隐藏向量反馈受到此bug影响。

### 5.3 不能被高恢复率掩盖的现象

- **局部修回不等于下游恢复。** 多父节点试验的+11条件，每时点仍有35/795个下游节点观察在末两轮未恢复，集中在5个目标案例；这些目标自身已经修回。
- **A′有时看起来更“不传播”，只是保留旧答案。** 同样把u改错，在u刚算对时尚未计算的q会跟着错；整图完成后q可保留旧正确值。不能把后者称为检测并抵抗错误。
- **B存在错值依赖的例外。** graph142、pos128，正确值为`(10+5+10) mod23=2`。从干净起点写8后，1–16轮持续为8；其它21种错值最终回2。父输入正确仍失败，不符合“只要父对就总能重算”的无例外描述。
- **图上无依赖也不代表模型内部完全隔离。** 另一分支注错曾出现12个exclusive区域节点受损事件，之后恢复；深入归因按用户决定暂缓。

训练配置为`corruption_prob=0.05`、候选位置替换概率0.5、策略`last`；这些概率的作用层级不能与C的“约一半图次、一次一个节点”直接互换。训练审计表明，B主要在新槽位的EMPTY上接受腐蚀，而测试包含“已经算对后再改错”。它能处理后者是值得保留的行为泛化结果，但“所有更新都由错误检测触发”仍未被证明。

## 7. C后训练：到底得到了什么收益

### 7.1 延长保持监督：改善明显，但尚不能解释机制

第一批使用新1024/128图。从同一C₀出发，普通组D轮；长程组2D或3D轮。隐藏状态连续传递，额外轮次仍监督原题正确状态，不注入人工错误。

计算量代理匹配端点，新N32验证集、每图D+64：

| 训练组 | 新数据遍数/更新次数 | 节点VALUE | 节点四属性同时正确 |
|---|---:|---:|---:|
| 原C₀ | 未后训练 | 91.43% | 2.93% |

额外2D不是在所有档位/指标上都优于额外D。所有组128张图仍都出现过四属性失稳，D+64整图四属性全对为0。**长程监督有用，但尚不能区分“学会少漂移”和“内部不断修复”。** [原报告](../2026-11-15/c-long-pilot.md)

### 7.2 额外注错：传播和恢复出现了分离

第二批hold/noise/semantic均从原s2026/e143开始，2D、3遍、393步；训练数据相同。约一半图次在保持前半段给一个内部节点一次干预，semantic偏移覆盖1–22；noise扰动长度匹配语义替换的向量差。

六档统一协议，每档64图、到D+64，先逐图再六档等权：

| 权重 | 节点VALUE | 节点四属性同时正确 |
|---|---:|---:|
| 原C₀ | 79.60% | 2.19% |
| hold | 97.72% | 34.45% |
| noise | 96.84% | 27.65% |
| semantic | 96.79% | 34.30% |

与上一表的验证集、端点批处理和训练运行不同，不能跨表直接排名。此表中D轮基础求解接近满分，差异主要在后续；语法和运算字段保持正确，四属性损失主要来自VARIABLE，并伴随VALUE错误。四模型D+64整图四属性全对均0。

训练实际剂量也不同：1489次semantic计划都写入预期错值，其中1485次写前正确；noise写前正确的1481次中，仅24次变成错误VALUE，约1.62%。**同向量长度不等于同错误强度。** 因而不能用当前noise组判定“随机错误训练无效”。

在128图父子干预的保持时点，只改u时，q首轮仍正确为hold 12/128、semantic 34/128；但直接改q时，q首轮修回为hold 112/128、semantic 97/128。这支持“少一些初始传播，但没有更快局部修复”，不是总体纠错胜出。[注错训练](../2026-11-15/c-corruption-pilot.md) · [统一基础与父子评估](../2026-11-15/c-basic-evaluation.md)

## 8. 最近的持续错父与强度校准

这批只评估原C₀及hold/noise/semantic四份现有权重，没有新训练。

| 实验 | 操作 | 结果与意义 |
|---|---|---|
| 持续错父 | 128图、保持/晚期两个时点，连续2或4轮把u写成当轮异值来源；q原状或首轮同时改错；释放后看16轮 | 首轮q正确hold12/128、semantic34/128；第二次强制后两者均0/128。semantic的首轮优势没有抵抗住持续输入错误 |

## 9. 哪些结论可靠，哪些还只是解释候选

| 目前证据支持 | 仍待检验的解释 |
|---|---|
| B通常能覆盖已有错值，A′在所测内部节点上更接近保留已填答案 | B是否每轮无条件重算，或只在某种不一致下更新 |
| B的错误与恢复能沿依赖传播，且存在持续失败 | 是否形成某种固定点、哪些表示/注意力路径造成例外 |
| C数值完成与长程保持是两个不同能力；变量名读出经常更早退化 | VARIABLE漂移是否造成数值错误，还是共同状态变化的另一个读出 |
| 语义来源替换可产生特定下游错误，同值来源通常影响较小 | 能否得到只改变单一属性、其他计算信息严格不变的向量干预 |
| 长程监督明显改善所测单种子的长期数值保持 | 改善来自避免漂移还是纠正漂移；是否跨种子/独立测试成立 |
| semantic部分单次干预下传播较少，持续错父下优势消退，恢复不更快 | 是否学会保留旧答案、暂缓使用坏输入，或产生了更一般的鲁棒计算 |

| `reduce_batch`的factor-PAD裁剪缺口 | **已知实现缺陷，当前未修** | 不同字段PAD编码不同，继承逻辑没有按预期裁剪；本批保持共同配方，评估mask排除PAD。修后属于配方变化，需另行记录 |
| 服务器全量权重/原始轨迹 | **未在本地完整重放** | 目前审阅依据源码、审计、导出小表和报告；有来源核对不等于独立重跑所有模型 |

**建议下一步顺序（讨论用，不是新增执行授权）：**先完成B既有CPU残留链条；C用现有数据补“目标正确但下游受损”的联合分组与对照；随后固定独立评估集、预算和三种子范围，再决定中等噪声、语义注错、保持监督怎样组成正式后训练。当前不需要为了文档整理重跑GPU。
