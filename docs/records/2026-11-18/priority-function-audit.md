## 2. 读法与口径

每条 u→它的每个直接子节点 q（不只看 focal q；focal 标记保留）逐轮记录：

- **输入轴**：该轮 forward 前，u 的输入读出是否正确；四格为 `(u 输入读数, q 输出)`。
- **输出轴**：该轮 forward 后，u 的输出读数是否正确；四格为 `(u 输出读数, q 输出)`。
- 四格简写 `TT/TF/FT/FF`：第一位是 u 读数正确，第二位是 q 输出正确。
- `controlled`：其余父节点输入 VALUE 全部正确，且匹配参照分支在该轮 q 输出正确。pair 的 `q_wrong` 参照是自身，不能提供 `q_reference_correct`，所以直接 q 污染的后果改用 `both_wrong` 对 `q_wrong` 的配对比较。
- `qin ok/bad`：controlled 内 q 自己的输入读数是否正确。
- **关键限制**：这里的“正确”都只是解码字段；C 使用连续 hidden feedback，q 的输出由隐藏状态计算，不保证等于其解码输入父值。因此四格是观察证据，不是“计算通道”或“内部读取”的证明。

## 7. 解释、替代解释与下一步

- **可以直接回答的**：u 输出读数回正不等于 q 输出恢复。pair 第 2 轮约 70% 的“u 输出对、q 错”已不再有 u 输入错；持续释放 R1 也有 446/606 条如此。但把其余父节点、匹配参照和 q 自己的输入读数都纳入受控子集后，持续批的这类残差全部伴随 q 输入读数仍错（R1 qin ok=0），pair 第 2 轮也只有 44/363。故 **“读出修好”与“下游恢复”之间主要还隔着 q 自己的输入读出层**，不是已经证明的“q 计算错误”。
- **仍存的候选**：pair 的 114 个、持续 6 个、噪声 2,230 个 C edge-rounds；它们满足“解码出的 u/q 输入与 u 输出均正确、其余父与参照正确，但 q 输出错”。数量高度依赖来源与轮次（噪声集中在 s3/s6 r1–r2；持续只有 graph107 的 6 个），不能当成一般机制。
- **替代解释**：C 是连续 hidden feedback。解码出的 u/q 字段只是隐藏状态的四个投影；u 的扰动仍可能通过隐藏成分或注意力影响 q 的 forward。r1 噪声例子正是“q 输入读出正确但 q 输出错”，不能据此说 q 没有读取或使用了错误值，也不能把它命名为独立计算通道。另一种可能是匹配参照分支本身在隐藏状态上已分叉；本审计只能对齐解码字段和输出，不能对齐 hidden。
- **下一项有必要的干预（本轮未执行）**：在 C 类型轮次做同一绝对时点的 hidden-state 匹配替换——只把 q 位置（或 u 位置）的 hidden 换成 clean 回放的 hidden，其他位置保持；若 q 输出恢复，支持“隐藏状态污染”而不是“q 计算规则错”。再做一次把正确 q 输入行连续写回的对照；仍不应把解码重嵌入当作连续反馈。该干预需要新的授权和显存/时序检查，本批不启动。

## 8. 边界与产物

- 只做 CPU 读取；没有重新加载权重、没有 GPU、没有新训练、三种子、真实改题、层/头干预或持续污染训练。四权重仍是各源 meta 里的 initial s2026/e143 与腐蚀 pilot 的 hold/noise/semantic final。
