## 0. 划分方法与使用规则

按“要回答的问题”分六个方向，不再仅按B/C模型分工：

| 编号 | 方向 | 独立问题 | 控制住什么 |
|---|---|---|---|
| E | 定义与评估 | 什么叫潜状态错误、恢复，怎样测？ | 先不改变模型 |
| M | 现有模型机制 | 现有B/C为什么更新、冻结、漂移或恢复？ | 优先固定权重做干预 |
| W | 任务与工作空间 | 已有状态能否重新赋值、槽位能否复用，能计算多长/多宽？ | 先固定模型，明确新任务语义 |
| T | 训练配方 | 同一架构怎样训，才更会保持和修错？ | 主要改变数据、时点、监督及预算 |
| U | 更新结构 | 是否需要把定位、计算、提交分开？ | 新结构内做同条件消融 |
| G | 架构归因与推广 | 收益是否来自Loop特性，能否超出当前模运算任务？ | 匹配任务、训练信号与资源，分开控制变量 |

“相对正交”不是互不依赖。E是共同基础；M提供事实；W、T、U是三类不同干预；G检验结论是否能推广及其架构归因。B/C是这些方向的实验对象，不再各自复制一套定义和评估。

每个方向按1–6推进，但不要求跨方向排成长队。任务状态统一：**待讨论 → 已定方案 → 待实现 → 待小验证 → 待执行 → 待审阅 → 完成/延期**。下面未勾选项均为待办，已有结果只作为基础，不重复算新任务完成。

每次只把下一项已定方案转为执行交接，写清权重、数据、操作、指标、预算与产物。GPT负责设计/核心逻辑/审阅，执行agent负责服务器适配、小验证和执行；服务器共享工作树仍按既定串行交接，运行中不更新工作树。旧看板授权和延期项不因本文自动改变。

## E. 定义与评估：先把“我们在测什么”讲清楚

**已有基础**：节点VALUE/四属性两个核心指标、逐轮轨迹、同值来源控制、持续恢复等。尚未形成完整的潜状态功能判据。

1. [ ] **E1 定义三个层次。** 明确读出异常、功能性错误、功能恢复；把原题污染、合法题面更新、槽位复用的真值分开。输出一页术语表和正反例。不能用“最终修好了”反过来决定是否属于错误样本。
2. [ ] **E2 建立功能检查。** 固定读出正确/错误×实际依赖计算正确/错误四格；用尚未求解、重新求解或匹配后续计算排除“子节点仅复制旧答案”。保留主轨迹，诊断分支另记；多个功能检查只是证据，不是穷尽内部状态。
3. [ ] **E3 定义时点与事件。** 分尚未完成、刚完成、长期完成；训练深度内与深度外推分列。区分首次回正、持续恢复、回正再错、永久未恢复；只证明有限窗口稳定，不直接叫收敛。
4. [ ] **E4 固定分母和指标。** 保留节点VALUE/四属性，图内比例再逐图等权，同时给原始计数；并列合格、实际注错、实际受损、恢复数，说明EMPTY/no_value与尚未就绪的区别。报告健康节点损伤和共同分母净收益，不只比较不同分母的恢复率。
5. [ ] **E5 冻结正式评估集。** 训练/采错/选配方/测试分开；按深度、活跃宽度、父数、时点、错误种类分层，固定选模规则与来源。保留全部资格结果及共同资格子集，不能只留下容易恢复的模型/图。
6. [ ] **E6 形成统一评估交付。** 定义最小导出格式：权重/代码/数据版本、实际输入输出、干预、节点身份、时点与预算、计数及案例。优先复用现有脚本，按方向需要扩展，不为了统一而重跑全部历史结果。

**完成标准**：不同模型或训练组的同名指标含义一致；读出改善不会被直接写成计算恢复。
**下一步**：先讨论E1/E2/E4；E5应在正式T训练前冻结。

## M. 现有B/C机制：解释当前现象，不先改训练

**已有基础**：B完成后及多父节点注错、残留链条；C时点/来源/联合修复/持续污染/噪声实验。这里补缺口，不复刻已完成全矩阵。

1. [ ] **M1 建立待解释现象清单。** 从已有轨迹整理B“父值正确、子值持续错”和C“目标读对、下游仍错”等案例，配同图成功节点、相近图与健康对照。分清事实与假设，避免只解释一张特殊图。
2. [ ] **M2 比较同一错误的不同产生方式。** 对齐位置、错值、时点，比较直接写错、由上游传播、自然失错；加入清空后重算和同值写回。比较早期/完成后、内部/叶变量/sink以及单父/多父，按现有覆盖补缺，不全量重复。
3. [ ] **M3 识别恢复所需的信息。** 分别干预父状态、祖先/题面证据、节点自身旧状态，确定恢复依赖哪条路径。移除信息与输入分布破坏分开控制；原题面保留在序列中不等于每轮有独立输入注入，按各模型实际架构实施。
4. [ ] **M4 检验是否选择性更新。** 健康/错误节点配对，结合父值冲突、持久错误和必要的错值切换，区分保值、持续重算、按冲突更新。重算出同值不会出现在输出差分中，要用因果干预而不只看值变没变。局部自洽控制须先补全合法构造，再解除既有延期。
5. [ ] **M5 分开防漂移与修复。** 对C自然错误和受控错误分别统计：发生频率、首次功能损伤、传播、恢复和再犯；联合观察VARIABLE/VALUE。变量名读出改变不直接证明寻址改变；单点修复不够时，再比较父/子/局部联合修复。
6. [ ] **M6 把现象检验到相邻场景。** 预先固定新的图、错误值、时点、节点角色和可用种子，验证机制解释的适用范围。训练污染审计作为解释依据，复用既有结果；新增训练版本才补对应审计。输出“支持/排除/未区分”假设表。

**完成标准**：每条机制解释都有对照和适用范围；“能恢复”不自动等于检测到错，“值不变”不自动等于没计算。
**下一步**：M1整理已有证据，然后定M2最小补充，不立即重开大矩阵。

## W. 新任务与可复用工作空间：检验实际计算收益

**已有基础**：题面更新D1/D2/D3有邻近实现；固定槽位长期复用尚未完成协议或实验。

1. [ ] **W1 定义重新赋值协议。** 在同一旧状态上比较原题不变的污染、合法新题面、从空白求新题；明确何时应恢复旧值、何时必须接受新值。对接已有D1/D2/D3，不把代码存在当正式结果。
2. [ ] **W2 做无需新训练的适应诊断。** 现有A′/B/C分别测试新题接受、旧值残留、下游更新和稳定性，先从窗口内一次重新赋值开始。连续路径区分保留隐藏状态与解码重嵌入，不把后者称始终连续。
3. [ ] **W3 定义固定槽位执行器。** 区分逻辑节点、变量名、物理槽位和token位置；规定版本、最后使用、回收、旧方程失效、新指令进入和输出保存。外部调度不代算、不灌真值，计入外部内存及接口成本。
4. [ ] **W4 扩展复用长度与宽度。** 先一次复用，再多次；分别改变累计节点数、依赖深度、峰值活跃值数。比较全重置、只清回收槽、保留旧值；不把重命名就当成突破序列限制，也不宣称固定槽位支持任意宽图。
5. [ ] **W5 测量丢弃证据后的修复边界。** 在旧证据释放前/后、跨版本引用等条件下注错，研究提交前检查、保留窗口、备份/重新计算的成本。没有恢复信息的条件明确标注，不要求模型凭空找回旧值。
6. [ ] **W6 轻微后训练与留出推广。** 在明确的复用失败上做普通接口适配与纠错适配对照，同预算测试未见复用次数/深度/活跃宽度。先固定外部调度，学习调度另列后续，不同时引入两种难题。

**完成标准**：在明确且计入资源的执行协议下，知道可用工作空间支持多少可靠累计计算；能区分更新失败、寻址/版本失败、容量不足。
**依赖**：W1依赖E1；W3在W1/W2后定型；W6与T共享训练规范。

## T. C+训练配方：固定主架构，找有效的训练改变

**已有基础**：s2026的长程、hold/noise/semantic小试；尚未正式三种子比较。欠拟合旧s2025不重新纳入主评估。

1. [ ] **T1 固定起点与预算。** 明确三个可用C₀权重、普通续训基线、模型选择规则、数据隔离与总计算预算；同时记录优化步数、监督轮数、样本数和donor计算，不假装它们都能同时相等。
2. [ ] **T2 定长程保持方案。** 基于已做额外D/2D小比较，选择固定或随机保持长度的候选；D定义一致。分完成率、少犯错与失错后恢复，避免把整个收益都叫纠错。
3. [ ] **T3 定间歇人工注错方案。** 语义错误与噪声分别校准，按计算中/刚完成/长程、单次/间歇多次、位置与功能损伤分组。参考B实测污染规模但不照搬EMPTY槽；保留同值来源对照，L2相等不作损伤相等。
4. [ ] **T4 定自然失败训练方案。** 只在训练图采集自然失效并回放或重放；记录是否影响依赖计算、是否自行恢复、失败分布及梯度截断。保持正常样本比例、更新失效缓存；用正确标签继续监督不等于强化学习。
5. [ ] **T5 先分组消融，再混合。** 普通续训、保持、保持+语义、保持+噪声、保持+自然失败先独立；按开发集结果决定少量混合候选，最终测试不反复调参。本阶段不引入新定位结构。
6. [ ] **T6 正式三种子与训练路径核对。** 小规模配方选定后做三个种子的同协议比较，报告负收益及差异。后训练是第一阶段；只有需要回答“原训练是否限制了新能力”或原型有效后，再做从头训练对照，明确两者回答不同问题。

**完成标准**：能说明收益来自保持、抗扰动或恢复，而非更多训练或错误剂量不同；每个改善有干净能力与健康损伤对照。
**依赖**：T正式执行前完成相关E协议；T2/T3可用既有机制证据，不必等全部M结束。

## U. 更新结构与计算粒度：定位、计算、提交怎样组织

**已有基础**：设计候选，未实现。REGRET/MODIFICATION为未训练启用的历史辅助字段，不能直接当有效控制信号。

6. [ ] **U6 再做同前向与流水版本。** 双前向有效后，尝试前段块定位/后段块计算，以及本轮执行同时规划下一轮；处理结果可见时机、计划过期和同步。实测计算与延迟；密集算完再mask写入不声称省FLOPs。

**完成标准**：定位真的控制了更新，并能提高可靠性或资源效率；能指出代价和失败条件。
**依赖**：U1/U2依赖E1/E2及最小场景；新结构不与T基本配方同时混成一组。

## G. Loop归因与跨任务推广：检验研究价值

**已有基础**：当前A′/B同架构训练对照不能回答“Loop相对普通Transformer的优势”；新的对照尚未完成。

1. [ ] **G1 明确架构比较轴。** 共享权重循环、非共享权重展开、显式离散/文本反馈分别控制什么；区分整图更新、逐token生成、额外输入注入。先选一个最小架构比较，不立即铺开所有模型。
2. [ ] **G2 建立公平资源与信息对照。** 参数匹配和计算匹配分开；相同任务、错误、监督信息、选模规则。CoT能看到额外文字历史时，明确它拥有的存储和计算资源。
3. [ ] **G3 测多轮计算的净收益。** 固定输入/生成前缀和随机性，改变循环预算，分未完成→完成、功能错误→恢复、正确→受损；记录实际代价。训练深度内和外推另报，不用只选最终成功轨迹。
4. [ ] **G4 选择第二类任务。** 优先可判定依赖与内存需求的程序执行/多步算术等，保留不同组合、深度、活跃宽度的留出轴；不把图换成文字就当跨任务验证。再考虑更开放任务，避免一开始失去可解释性。
5. [ ] **G5 在已有Loop语言模型上验证现象。** 候选Huginn/Ouro等须先核对实际实现、训练覆盖深度、完整读出与缓存协议；直接答案与CoT分开，token化与中间读出有效性检查。它是外部验证支线，不强行搬用整图模型的一轮一层语义。
6. [ ] **G6 整理贡献与反例。** 对照相关工作，检验究竟新增了可复用任务、可靠更新方法、计算收益还是机制证据；主动保留无收益/反例。根据结果决定收拢主线，不预先保证创新，也不把六条线全部完成作为投稿前提。

**完成标准**：至少有一个明确、可复现的主张，知道哪些收益属于共享循环、训练信号或工作空间接口；不靠重新命名普通状态修复建立独特性。
**依赖**：G1/G2应早设计，避免后期补不公平对照；G4/G5的规模化执行在核心现象/方法清晰后。

## 7. 推进顺序：先小闭环，再扩展

| 阶段 | 重点编号 | 交付与进入下一阶段的条件 |
|---|---|---|
| 第一轮：定可执行问题 | E1/E2/E4；M1；W1；G1/G2方案 | 功能错误有实例；新旧真值明确；知道未来架构对照怎么做 |
| 第二轮：最小诊断 | M2；W2；E5/E6；T1–T3方案；U1 | 明确现有权重的失败与健康对照；正式训练前评估冻结 |
| 第三轮：分别验证改变 | W3/W4；T选定小试；U2/U3 | 每条线各有最小成功/失败结果，不把全部因素合在一组 |
| 第四轮：归因与扩展 | 按结果选择M3–M6、W5/W6、T4–T6、U4–U6、G3–G6 | 先消融，再跨种子/任务；收益不足时修正或停止相应候选 |

这些是顺序建议，不是“所有任务同时排进GPU”。每条线只推进有必要的下一步。架构公平性设计要早，昂贵跨模型实验可以晚；定义与评估可以逐步冻结，不要求先解决潜状态的一切哲学问题。
